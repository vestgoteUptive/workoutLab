## Traps (condensed — full history in journals; 09-28..10-01 and 10-02..10-04 archives)
- Lane/grant hygiene: no `git diff main...HEAD` assertions in committed tests (checks skip silently in CI); grants read at `merge-base origin/main HEAD` so push ticket files before a build; `git diff main...HEAD` (three dots) for lane checks.

- Verification: `pnpm -w typecheck lint test --force --concurrency=1` + `test:repo-checks` (a separate script, not covered by the first) + `format:check` + `check-all.mjs`, and **e2e** for anything touching `apps/web/src/**` or `tests/e2e/**`. A contract change (openapi/data-model/engine-rules/tokens) still forces `--force`.
- jsdom has no CSP (TR-0036): runtime eval/compile passes Vitest but breaks the built app — precompile, the build.test.ts bundle scan guards it.
- Offline e2e rows for built screens must seed data and assert built content (D-0091 §1); a URL check alone narrows but doesn't close a redirect race. Binary-condition ACs need the other value tested too.
- **A merge-and-gate script must stop on a failed `git merge` — `&& echo MERGED` alone is not enough, even under `set -euo pipefail`** (T-0471, 2026-10-05): a real conflict left `main` mid-merge with an unresolved `UU` file, but the script's later stages (typecheck/lint/test, repo-checks, check-all, full e2e) don't themselves depend on the merge succeeding, so they ran anyway against the conflicted tree and all reported `CHECK_OK`. Add an explicit check right after the merge line — `git status --porcelain | grep -q '^UU' && exit 1`, or test `git rev-parse -q --verify MERGE_HEAD` — don't rely on `&&`/`set -e` chaining alone.
- Never push main while a merge on it is still being verified. Never launch a second merge-and-gate script before confirming the first one's gate actually finished (concurrent turbo runs on one tree corrupt each other's cache and produce false failures).
- `run_in_background: true` on a command that itself backgrounds with `nohup … &` reports "completed" when the outer shell forks, not when the real work finishes — poll a sentinel file instead.
- `beforeunload` never fires on iOS Safari (WebKit/bfcache); `pagehide` fires reliably everywhere but only as part of unload itself, too late to gate a same-tick timer. Name the actual event and confirm it fires on the real target before trusting an "unload is imminent" inference.
- Never leave a QA/review agent running on a worktree just sent back for rework (check `ListAgents` first). A build resumed after an outage may report a "finding" another ticket already fixed upstream in the meantime — merge current `main` and re-verify before trusting it.
- **Always `git worktree add`, even for one-file docs-only tickets** — two agents told to skip it and work directly in the shared checkout will race each other's `git checkout`, and one's uncommitted edits can end up under the other's branch pointer. Small is a reason to skip review+QA (D-0178), never a reason to skip the worktree.

- **A merge-and-gate script piping each stage through `tail -N` needs `set -o pipefail`, not just `set -e`.** Without it, `set -e` only checks `tail`'s exit code (always 0), so a real test failure never stops the script — it prints a false `CHECK_OK` and keeps going (2026-10-03).
