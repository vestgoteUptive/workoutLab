## Context
The orchestrator wants phase 3 finished before phase 4. T-0482 (UF-02) is in build, and T-0481
(UF-11) has just landed. It asked for 2 or 3 more self-contained phase-3 `todo` tickets, in lanes
that don't overlap UF-02, UF-11 or each other.

Candidates checked against main `003c20d`:
- **The check-lane-paths cluster** (T-0336, T-0337, T-0338, T-0339, T-0347, T-0348; lane `infra`;
  dep T-0320 is `done` in board-done). All six change `.github/scripts/check-lane-paths.mjs`, so
  only one can be in flight at a time. If several were made ready together, they would just queue.
  T-0336 and T-0337 change the same pair of functions (`resolveChangedPaths`, and `runCheck`'s
  no-base branch) and share the injected-`git` test seam.
- **T-0322** (web-shell, no deps). `apps/web/scripts/check-bundle-size.mjs` checks whatever
  `dist/` exists, throws a raw ENOENT when it's missing, and prints nothing on success. There is
  no root `check:size` script. Five ticket files carry a workaround note for this.
- **T-0330** (web-shell; dep T-0319 is `done`). Three web-shell test files cast `SelectSpy.from`
  because it is typed `ReturnType<typeof vi.fn>`.
- **T-0341** (web-shell; dep T-0306a is `done`). Skipped: its own trigger, "once UF-01.3 or UF-05
  needs them" (D-0079 §5), isn't clearly met. The labels live in `flows/uf-04.ts` and `uf-05.ts`,
  and a UF-11 test helper repeats them. Grooming it means first deciding where shared labels go,
  which is T-0342's question too. Better groomed with T-0342.

## Decision
1. **T-0336 → ready, with T-0337 folded in. The other four check-lane-paths tickets stay `todo`.**
   - When both `origin/main` and `main` resolve to different merge bases, use the one nearest
     HEAD: `git merge-base --is-ancestor <originBase> <mainBase>` exit 0 picks `main`'s base,
     and anything else keeps `origin/main`'s (today's choice).
   - Equal bases cost no extra git call. The return shape stays `{ changed, note, base }`.
   - In CI (`CI` matching `/^(true|1)$/i`) on a ticket branch, a missing base or a failed diff is
     a `no-diff-base-in-ci` finding at `.github/workflows/ci.yml:1`. Off CI, it stays a note.
   - The check still never fetches. Grants are still read from the base (D-0074 §5). Local `main`
     only exists on a laptop; CI checks out `origin/main` alone.
   - Next in this file, one at a time: T-0347 (ownership.yaml from the base) is the most
     security-relevant, then T-0338, T-0348, and T-0339 (which needs a decision first).
2. **T-0322 → ready.**
   - A new exported `runSizeCheck(distDir, { sourceRoots })` does the CLI work and returns
     `{ code, out, err }`.
   - A missing manifest is one sentence on stderr and exit 1.
   - A manifest older than the newest shipped source file is exit 1. Shipped source means
     `apps/web/src`, `index.html`, `vite.config.ts`, and the engine, shared and design-tokens
     `src`, minus `__tests__` and `*.test.*`. Equal mtimes are not stale.
   - A fresh `dist/` prints `entry <n> B gzip` and `max chunk <n> B gzip <file>` (or
     `max chunk none`).
   - The root gets `"check:size": "pnpm --filter @workoutlab/web check:size"`. The root
     `package.json` is infra's, so it's granted by name for that one line.
   - `check:size` never builds. A stale build is reported, not silently repaired.
3. **T-0330 → ready.** `SelectSpy.from` becomes `Mock<(table: string) => SelectFrom>`, and the
   three web-shell casts go. Consumers in `features/**` are left alone. If the tighter type breaks
   one, that becomes a follow-up for its lane.
4. **Lanes.** The three tickets touch three disjoint sets of files:
   - T-0336: `.github/scripts/check-lane-paths*`;
   - T-0322: `apps/web/scripts/check-bundle-size*` and the root `package.json`;
   - T-0330: five test files under `apps/web/src/{lib,app}`.

   None touches `features/UF-02/**` or `features/UF-11/**`, so all three can run in parallel
   with each other and with T-0482.

  roots written next to the manifest, which needs a vite plugin and so its own ticket.
