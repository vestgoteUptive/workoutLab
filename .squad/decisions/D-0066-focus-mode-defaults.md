## Context
User flows v2 gives the UF-09 screen table and the loop (09.3 → 09.4 → 09.5 → 09.3; between exercises 09.8 → 09.6 → 09.3). NFR-TIME-1…4, NFR-OFF-2, NFR-PERF-4 and NFR-A11Y-2/4/5/6 set the numbers. D-0057 and D-0062 define the pre-fill. Still open: where the in-progress state lives (the `lib/offline` queue removes flushed sets, so it can't tell "which set is next"); when the set row is written; what RIR "1–2" stores; what the second set pre-fills after the user edits the first; the rest length; whether warm-up moves are logged; what a null weight does to auto-save; plate loading; swap; and where "End" goes, since UF-03.3 has no route yet. There is also a known engine gap: rule 7.1 costs timed items at `defaultDurationS`, while `prefill.durationS` can reach 120 s, so a plan can overrun its budget (T-0219). And a clamped timed pre-fill can report `hold` while the duration went down (D-0062 §5).

## Decision
1. **State machine.** A pure reducer `focusReducer(state, event)` in `features/UF-09/machine.ts` holds the states `getReady | warmup | set | confirm | rest | timed | betweenItems | timeCheck | next | paused | done`. `betweenItems` is transient: it is resolved at once to `timeCheck` or `next` (§11). Timers are wall-clock timestamps (`startedAtMs`, `durationS`, accumulated `pausedMs`), never tick counts (NFR-TIME-1). `remainingS = max(0, durationS − floor((now − startedAtMs − pausedMs) / 1000))`.
2. **Persisted focus state.** After every transition, the state is written synchronously to `localStorage["wl-focus:<sessionId>"]` (`{version: 1, …}`). Reopening `/session/<id>` restores it, including running timers, which are recomputed from the timestamps. Without a stored state, it starts at UF-09.1 item 0. The plan comes from the IndexedDB session row (`offlineDb().sessions.get(id)` → `parseSessionPlan(row.plan)`). If there is no row, the host shows "This workout isn't on this device" with a link to `/`.
3. **Done set writes first.** "Done set" (UF-09.3) calls `recordSet` with the pre-filled values right away (the `client_id` is born at Done set, NFR-SYNC-1). The pressed state appears in < 100 ms without waiting for IndexedDB (NFR-PERF-4). The machine moves to UF-09.4 only after the write resolves (NFR-OFF-2). Changes on UF-09.4 are saved with `editSet` (`edited_at` only, D-0015).
4. **UF-09.4 auto-save.** It auto-saves after 5 s unless touched. Any touch cancels the auto-save for that set, and Save is then required. Auto-save is **off** when the pre-filled weight is null on a loaded lift (null means "ask", D-0057): the weight field is empty and Save accepts an empty weight (`weight_kg` null).
5. **RIR.** The options are None / 1–2 / 3+ and store `rir` 0 / 2 / 3. When the user doesn't pick one, `rir` is null. RIR is logged, not used (D-0026).
6. **In-session pre-fill.** Set 1 of an item uses `item.prefill` exactly. Set k > 1 uses the weight and reps of set k − 1 as the user saved them, falling back to `item.prefill` when set k − 1 had a null value. The back-off set (`item.backoff`, logged with `backoff: true`) uses `backoff.weightKg`/`backoff.reps`. The weight step is the exercise's `incrementKg`. Bodyweight exercises (`externalLoad: false`) show no weight control and log `weight_kg` 0.
7. **Rest.** `REST_COMPOUND_S` (120) or `REST_ISOLATION_S` (60) from `@workoutlab/engine`, chosen by the library `type`, never as literals. It starts automatically after Save. −15 s is floored at 0, and +15 s has no cap. At `remainingS ≤ 10` the ring and label use `warn`, and the cue plays. At 0 it shows "GO". There is no rest after the last set of the last item.
8. **Warm-up.** It uses `plan.warmup` moves at their `durationS` (40 s) and auto-advances. Restart resets the current move, and Next move skips it. Skip warm-up (UF-09.1) goes to item 0. Warm-up moves are **not** logged as sets (they never count, D-0004).
9. **Timed sets (UF-09.7).** 3 s "Get in position", then a hold of **`prefill.durationS`** (D-0062 consequence; `item.durationS` is only the costing value). At 0 the machine auto-logs `recordSet({kind: "timed", durationS: prefill.durationS})` and goes to rest. When a timed pre-fill has `kind: "hold"`, the copy never says "same as last time" or "hold at last time's". It shows only the target ("Hold 2:00"), because a clamped duration can be below the last one (D-0062 §5). The overrun from rule 7.1 costing is the engine's T-0219. Focus mode renders the engine values as they are, and T-0304 doesn't depend on T-0219.
10. **UF-09.6 Next exercise.** A 60 s set-up countdown. At 0 it moves to UF-09.3 on its own. "I'm ready" moves at once.
11. **Time check (UF-09.8).** It runs only when an item's last set (and its rest) is done and another item follows, never mid-item (NFR-TIME-4): `timeCheck(workout, {elapsedS, nextItemIndex})`. `elapsedS = floor((now − started_at − pausedMs − (warmupInBudget ? 0 : warmupSpentMs)) / 1000)`. It is shown only when `show` is true, with `minutesBehind` (board note D-0047). The planned finish is `started_at + budgetMin × 60 s + pausedMs`, and the projected finish is `now + (projectedS − elapsedS)` of the chosen option. Continue keeps the plan. Trim or Skip next replaces the not-started items with `option.items` and saves the new plan through `upsertSession` (same id, board note D-0047). The `Workout` passed to `timeCheck` is built from the session row: `plan`, `budgetMin = time_budget_min`, `warmupInBudget`, `energy`, `sessionReasons: []` and `itemsTotalS`/`totalS`/`unusedS` as the Σ of `costS` (rule 8 reads only `plan` and `budgetMin`).
12. **Paused (UF-09.9).** Every timer stops (pausedMs accumulates). It shows elapsed, "left" = `ceil(max(0, budgetMin × 60 − elapsedS) / 60)` minutes, and sets done / planned sets. Actions: Resume · Skip to next exercise · How to (`/library/<id>`, returning resumes paused; it may later be replaced by the `ExerciseHowTo` seam, D-0067 §4) · End workout (confirm → `upsertSession` with `ended_at = now` → navigate to `/session/<id>/summary`, the UF-03.3 route from T-0318, built by T-0305b).
   **Seams (aligned with D-0067 §4–5).** T-0304 doesn't build Swap (UF-05.1, T-0306b) or List view (UF-03.1, T-0305a). It leaves:
   - `features/UF-09/seams.tsx`: `pauseSeamActions` (rendered on UF-09.9 after "Skip to next exercise") and `nextSeamActions` (rendered on UF-09.6 next to "I'm ready"). Each is an ordered array of `{id, label, render(ctx)}` and is **empty** in T-0304. T-0306b adds `swap` to both arrays and T-0305a adds `list-view` to `pauseSeamActions`, each editing only `seams.tsx`. An action's `render` returns an overlay that the host shows in place of the paused screen (still one task on screen, principle 1).
   - `useFocusSession()`, exported from `features/UF-09/index.tsx` and documented in its JSDoc. It returns `{sessionId, plan, workout, state, currentItemIndex, currentSetIndex, loggedSets: {clientId, itemIndex, setIndex, exerciseId, reps, weightKg, durationS, rir, backoff}[], rest: {remainingS} | null, elapsedS, replaceItem(index, item), recordSet(input), editSet(clientId, patch), deleteSet(clientId), resume(), finish()}`. Writes go only through `lib/offline` (D-0067 §5). `replaceItem` swaps a not-started or current item and saves the plan with `upsertSession`.
13. **Plate loading** (UF-09.3 "Each side: 25 + 15 kg") is out of v1: there is no bar or plate inventory. It is a Phase 5 idea.
14. **Offline icon only.** Focus mode renders `<OfflineStatus variant="icon">` in the chrome, never text or a banner (NFR-OFF-6).

## Consequences
- T-0304 is split into T-0304a (machine + host + persistence), T-0304b (the set loop: 09.1, .3, .4, .5, .6), T-0304c (09.2 warm-up, 09.7 timed, wake lock, cues, reduced motion) and T-0304d (09.8, 09.9, end, the offline/keyboard e2e).
- web-shell follow-up: a route `/session/:sessionId/summary` → UF-03.3 (T-0305). Until it exists, react-router's unknown-path rule sends the user to `/`.
- T-0306 wires Swap into UF-09.6/UF-09.9 through the `replaceItem` event (it needs an extra-path grant on `features/UF-09/**`, or a hand-off module).

## Revisit when
- T-0219 changes rule 7.1 costing (then the time check becomes accurate for timed items; no UI change).
- Users edit the pre-filled weight on more than 30 % of sets (the D-0026 trigger).
- Real use shows that the 60 s UF-09.6 auto-advance is too short or too long.
