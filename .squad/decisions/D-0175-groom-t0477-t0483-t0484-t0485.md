## Context
Five board rows were groomed against `main` at `7ea4276` (T-0418, T-0421, T-0414 and T-0906
merged). Each of these points changes what a test asserts.

- **T-0477.** `REST_STARTABLE` (`features/UF-09/machine.ts`) is `set`, `confirm`, `rest`, `timed`.
  Under an open List view the host keeps the clock running (`keepsClockRunning: true`), so the
  getReady countdown, the warm-up moves and the UF-09.6 set-up (`next`, 60 s) all run under the
  list. A set checked during any of them starts no rest. D-0172 §5 named only `getReady`/`warmup`,
  but `next` has the same gap: it is a countdown before a set, and the warm-up ends in it. The
  existing test `REST_START › from getReady/warmup/next/timeCheck/paused/done: the same state`
  pins today's no-op. Nobody has said what happens to the warm-up time when a rest replaces the
  warm-up.
- **T-0483.** The "Go" announcer test fakes only `Date`. It waits with `waitFor`'s 1000 ms default
  for the host's real 1000 ms interval, so there is no margin. Four other tests in the same file
  wait for the same real tick with `settle(1100)` (100 ms margin) or `findEl` polling. Faking
  `setTimeout` file-wide would break `waitReal`/`findEl` (they use the global `setTimeout`) and
  `waitFor`'s timeout. Faking `setInterval` file-wide would stop `waitFor`'s polling, which the
  AC-5 focus tests need: a focus change is not a DOM mutation.
- **T-0484 vs T-0485.** T-0906's regression assertion in `uf-03-list-summary.spec.ts`
  (`expect.poll(() => counters.attemptsSinceArmed()).toBeGreaterThanOrEqual(1)` and
  `abortedWhileOffline >= 1`) passes only because AutoSync's mount flush runs while
  `navigator.onLine` is false. The `page.goto('/session/S1')` after `context.setOffline(true)` is
  what makes the attempt. T-0485 guards exactly that flush, so with T-0485 merged first the poll
  times out and CI goes red. The comment in `uf-09-offline.spec.ts` (lines 220–229) says the mount
  flush "runs unconditionally". That would go stale too.

## Decision
1. **T-0477: `REST_START` from `getReady`, `warmup` and `next`.** `REST_STARTABLE` gains these
   three phases. `timeCheck`, `betweenItems`, `paused` and `done` stay no-ops: the time check
   must be answered (principle 2), and the other three are not running a step.
   - From `getReady`: `warmupSpentMs: 0` and `warmupStartedAtMs: null`, as `SKIP_WARMUP` does.
   - From `warmup`: `warmupSpentMs = max(0, atMs − warmupStartedAtMs)` and
     `warmupStartedAtMs: null`, as `RESYNC` already does when list logs end the warm-up. The
     warm-up does not resume after the rest.
   - From `next`: the warm-up fields are unchanged.
   - In every case `phase: "rest"` and the timer is `restFor(exerciseId)` at `atMs`.
     `itemIndex`, `setIndex`, `loggedSets` and `skippedItems` are unchanged. `REST_END` then
     finds the first free set of `itemIndex` (`setAfterRest`, `after = setIndex − 1`).
   - This is a reducer change with no overlay flag. The only dispatcher of `REST_START` is
     `startRest` (`session.tsx`), and only the List view calls it. A source test pins that no
     other non-test file in `features/UF-09` dispatches `REST_START`.
2. **T-0483: drive the tick, don't wait for it.** Each test in `rest.test.tsx` that waits for the
   host's re-render after `vi.setSystemTime` fakes `Date`, `setInterval` and `clearInterval`
   (never `setTimeout`, `setImmediate`, `queueMicrotask` or `nextTick`), and does so *before*
   `openList` mounts the host. It then calls `vi.advanceTimersByTime(1000)` inside `act`. The
   other tests keep today's Date-only clock. The asserted values and test titles don't change.
   No timeout is raised.
3. **T-0484: one offline gate for e2e.** `tests/e2e/fixtures/offline.ts` exports
   `goOffline(page, context)`. It arms an abort gate for every non-`GET`/`HEAD` request to
   `${VITE_SUPABASE_URL}/rest/v1/**` on `page`, then calls `context.setOffline(true)`. It returns
   `{ writesFulfilledOffline(), writesAbortedOffline(), goOnline() }`. `goOnline()` disarms the
   gate, then calls `context.setOffline(false)`. Reads still fall through to the spec's mocks.
   The gate never decides whether a read would have worked offline.
   - **No offline spec may require a write attempt after going offline.** The proof that the
     gate is live is the fixture's own self-test: a forced `fetch` POST under the gate. It is not
     an app flush that a later product change may legitimately remove. T-0906's
     `attemptsSinceArmed() >= 1` poll and `abortedWhileOffline >= 1` become
     `writesFulfilledOffline() === 0`. While writes are refused, the queue can't drain, so the
     `sets` read needs no ordering.
4. **T-0485 depends on T-0484.** The mount-flush `navigator.onLine` guard ships only after T-0484
   has removed the dependency in §3. T-0484 proves this with a temporary local copy of the
   T-0485 guard (AC-6). The guard is hardening only. No e2e may rely on it.
5. **T-0478 is unchanged and ready.** Its deps are done, and its assumptions hold on `main`:
   `FocusSession` has `workout`, `timeZone` and `replaceItem`; `SwapSheetProps.timeZone` exists;
   UF-08 already imports `features/UF-05/index.js`. It and T-0483 both edit
   `features/UF-03/__tests__/list-helpers.tsx`, so they don't run in parallel (D-0071 §1).

## Consequences
- T-0477 changes one existing UF-09 test (the no-op row loses `getReady`, `warmup`, `next`). The
  ticket names it.
- T-0483, T-0478, T-0464, T-0472 and T-0473 all sit in lane `web-feature:UF-03`. Run them one at
  a time.
- After T-0484, a new offline spec that reads the queue uses `goOffline`. T-0484's audit lists
  any older site that still needs it, as follow-ups.

## Revisit when
- Users report the warm-up "vanishing" after checking a set from the list during it (§1). The
  alternative is to keep the warm-up and start no rest.
- An offline spec needs reads to fail too (§3): give `goOffline` an option, not a second helper.
