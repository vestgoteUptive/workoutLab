## Context
The four tickets were checked against `main` after T-0304g, T-0307b, T-0422 and T-0440 merged, with
T-0308a merging, T-0415 and T-0436 in QA and T-0416 in build. That check left these points open:

1. **Back with an overlay open (T-0394).** D-0123 §3 says Back "closes the overlay back to UF-09.9".
   On `main` the host's `close()` doesn't end paused for two overlay kinds:
   - a `keepsClockRunning: true` overlay (the List view, T-0416) closes with `RESYNC`, which shows
     the running step;
   - a `keepsClockRunning: false` overlay opened from a running UF-09.6 (Swap on Next exercise)
     closes with `RESUME`.
2. **T-0438** is a two-comment fix in `session.tsx` and `host.tsx`. T-0415 (in QA) edits both files
   and T-0394 edits `host.tsx` after it.
3. **A failed UF-05 chunk (T-0451).** `React.lazy` caches a rejected import for the life of the page,
   so every reopen of Swap shows "Couldn't load alternatives." until a reload.
4. **UF-07.1 focus (T-0453).** After Remove, and after a picker Add, the focused button leaves the
   DOM or becomes disabled, so focus falls to `<body>` (WCAG 2.4.3). The delete confirm says
   `aria-modal="true"` but Tab leaves it and the form under it still takes input.

## Decision
1. **Back with any overlay open ends on UF-09.9, paused.**
   - `keepsClockRunning: true`: Back closes the overlay as `close()` does (the forced check point is
     cleared, `RESYNC`), then dispatches `PAUSE` at the same `atMs`.
   - `keepsClockRunning: false`: Back closes the overlay **without** its `RESUME`, so a Swap opened
     from UF-09.6 ends on UF-09.9 with `resumePhase: "next"`.
   - In both cases the guard is pushed again once. The overlay's own Close is unchanged.
2. **T-0438 folds into T-0394.** T-0394 is in the same lane, already serial after T-0415, and edits
   `host.tsx`. It also corrects the `SessionWrites` docblock in `session.tsx` and the
   `createSessionWrites` comment in `host.tsx`. The T-0438 board row closes when T-0394 merges.
3. **Retry a failed seam chunk in-page.**
   - A failed UF-05 import doesn't stick. The swap seam's lazy component is made again after a
     failure, so the next open (or "Try again") runs the import again.
   - The failure state shows "Try again" next to Close. Focus still goes to Close, as on `main`
     (T-0422 pins it).
   - A retry that fails again shows the same failure state. There is no automatic retry and no page
     reload: a reload mid-workout is the user's choice, and the focus state survives it anyway
     (D-0111 §6).
   - The importer stays a dynamic `import()` of `features/UF-05/index.js`, so D-0144 AC-A6 (no
     seam-mounted feature in the entry chunk) is unchanged.
4. **UF-07.1 focus after a list change.**
   - **Remove** row i: focus goes to the Remove button of the row now at position i. If the removed
     row was the last, it goes to the new last row's Remove. With an empty list, it goes to the
     search field when the picker is open, and to "Add exercise" otherwise.
   - **A picker Add:** focus goes to the search field. The user can type the next search at once.
     At 8 items, when every Add is disabled, this still leaves focus on an enabled control.
5. **UF-07.1 delete dialog.**
   - While it is open, every part of the form outside the dialog has the `inert` attribute.
   - Tab and Shift+Tab cycle between its enabled buttons, as UF-04's how-to does with its one
     button. Offline, Delete is disabled, so Tab stays on "Keep routine".
   - Escape, the initial focus on "Keep routine" and the return of focus to "Delete routine" are
     unchanged.
   - No native `<dialog>`/`showModal()`, because jsdom doesn't implement it.

## Consequences
- web-feature:UF-09: T-0394 (with T-0438) after T-0415. T-0451 after T-0416, because both edit
  `seams.tsx`.
- web-feature:UF-07: T-0453. T-0454 edits `EditorForm.tsx` too, so the two don't run in parallel.
- No contract change.
