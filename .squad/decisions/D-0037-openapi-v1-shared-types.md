## Context
`api/openapi.yaml` v0.1 has no schemas, auth or errors (gap B2). It lists five plain-CRUD paths (`/profile`, `/exercises`, `/exercises/{id}`, `POST /sessions`, `POST /sessions/{id}/sets`) that D-0001 routes through supabase-js + RLS, and its summaries cite v1 screen IDs (`UF-04` on `/workouts/suggest`, `UF-03, UF-08` on `/balance`, `UF-07` on finish). Several decisions hand T-0102 shapes that are named but not specified: D-0024 (Workout, session plan with start deficits), D-0025 (swap reason enum), D-0026 (pre-fill kinds), D-0027 (balance() and evaluateCheckin() outputs), D-0034 §1 (engine input types, ISO strings) and D-0035 (`sessions.plan` JSON, the v1b columns). The engine runs on the device (offline, principle 1 in focus mode), so `rankSwaps`, `timeCheck` and `evaluateCheckin` must not need a network round trip. The T-0100b review also found that `profiles_priority_areas_valid` accepts `'[2:3]={back,back}'`: `priority_areas[1]` is null and a null CHECK passes.

## Decision
This decision names the change to `api/openapi.yaml` (v0.1 → v1.0.0) and to `docs/data-model.md` (`profiles_priority_areas_valid`, the `sessions.plan` note).

1. **Paths (gap B2, D-0001).** Exactly three paths: `POST /workouts/suggest` (UF-08.1, UF-08.2), `GET /balance` (UF-10.1, UF-10.2) and `POST /sessions/{id}/finish` (UF-03.3). The five CRUD paths are removed. They stay plain supabase-js + RLS, typed by the generated DB types.
2. **Engine-only outputs are components, not paths.** `CheckinEvaluation` (UF-11.1), `SwapCandidate[]` (UF-08.3, UF-05.1), `TimeCheckResult` (UF-09.8), `PrefillResult` (UF-09.3, UF-09.4) and the engine inputs (`HistorySet`, `LibraryExercise`, `AreaTarget`, `EngineProfile`, `CheckinSession`, `PlanCheckin`, `TimeCheckProgress`) live under `components/schemas` with `x-engine-function: <name>`. The device calls the engine directly. A later ticket may add a path without changing the shape.
3. **Auth.** One scheme, `bearerAuth` (`type: http`, `scheme: bearer`, `bearerFormat: JWT`, the Supabase access token), applied globally. No operation is anonymous.
4. **Errors.** One envelope, `ApiError = {error: {code, message, requestId}}` with `additionalProperties: false`, as `application/json`. `code` ∈ `invalid_request` (400), `unauthorized` (401), `not_found` (404: missing **or** not owned, because RLS hides it), `profile_missing` (422: no `profiles` row or fewer than 9 `area_targets`), `internal` (500). Messages never contain an email or a user id (NFR-PRIV-7). There is no 403.
5. **Representations (D-0034 §2).** Instants are ISO-8601 strings with `Z` or an offset (`format: date-time` plus a pattern that requires the offset). Local dates are `YYYY-MM-DD` (`format: date` plus a pattern). `tz` is an IANA name: a string, and the function returns 400 when `Intl` rejects it. Areas are the 9-value enum `Area` in the fixed order. Every object schema is `additionalProperties: false`. Fields are camelCase.
6. **Engine input types = D-0034 §1.** `HistorySet` has exactly `clientId, sessionId, exerciseId, isWarmup, completedAt, editedAt, deletedAt (nullable), pending (optional), reps, weightKg, durationS (all nullable)`. `AreaTarget = {area, setsPer14d (integer ≥ 1), source (default|adapted|manual), updatedAt}`. `LibraryExercise` is a **superset** of D-0034 §1: `{id, name, kind (exercise|warmup), type, level, equipment[], areas (map Area → 1 | 0.5, D-0022), timed, incrementKg, defaultDurationS (nullable), externalLoad}`, so it stays assignable to the engine's narrower type. `EngineProfile = {goal, level, equipment[], rhythmMin, rhythmMax, priorityAreas[≤ 3], onboardedAt, planUpdatedAt}`, where `planUpdatedAt` maps from `profiles.plan_changed_at` (D-0035). `CheckinSession = {id, startedAt, hardSetCount (integer ≥ 0)}` (rule 9 "completed" = `hardSetCount ≥ 1`; T-0202 may reshape it).
7. **SessionInput / Workout / SessionPlan (D-0024, rules 7, 10, 13, 14).**
   - `SessionInput = {budgetMin (integer 1–480, matching the DB), warmupInBudget, energy (low|normal|high), shuffle (integer ≥ 0), mainLiftId (nullable), pinnedIds[], excludeIds[]}`.
   - `SessionPlan` (the `sessions.plan` JSON, D-0035) = `{version: 1, mainLiftId (nullable), warmup[≤ 4] {exerciseId, durationS}, items[≤ 8] WorkoutItem, startDeficits}`. `startDeficits` is an object with all 9 `Area` keys, each a number in [0, 1] (rule 5 deficit at session start, the input rule 8 trims by).
   - `WorkoutItem = {exerciseId, isMain, sets (integer 1–4), repsMin, repsMax (nullable for timed), durationS (nullable), costS, backoff (nullable {weightKg, reps}), prefill PrefillResult, reasons Reason[]}`. `PrefillResult = {weightKg (nullable), reps (nullable), durationS (nullable), kind PrefillKind}`.
   - `Workout = {plan SessionPlan, budgetMin, warmupInBudget, energy, itemsTotalS, totalS, unusedS, sessionReasons Reason[≤ 3]}`. The client writes `workout.plan` into `sessions.plan` at UF-08.4 Ready.
   - `Reason` is a `oneOf` with discriminator `code`: `main_lift` · `area_deficit {area, deficit}` · `days_since {area, days (nullable)}` · `recovering_skipped {area}` · `energy_low_trim` · `energy_high_backoff` · `swap {reason: SwapReason | null}` · `prefill {kind: PrefillKind}`. `SwapReason` = `equipment_taken | discomfort | variety | short_on_time` (null = no reason, the UF-05.1 default). `PrefillKind` = `first_time | carry | reentry | hold_after_break | increase | deload | hold | add_rep`.
8. **Other engine outputs.** `BalanceResult` = rule 11 exactly, with `areas` minItems = maxItems = 9, `days` exactly 14 numbers ≥ 0, `coverageStep` an integer 0–4 and `contributors[{exerciseId, weightedSets, lastDate}]`. `SwapCandidate = {exerciseId, muscleMatch [0, 1], timeCostS, equipment[], fitsBudget, bestMatch}`. `TimeCheckResult = {behindS (integer), show, minutesBehind (nullable, null when show is false), projectedS, trim {items WorkoutItem[], projectedS}, skipNext {items, projectedS}}`. `CheckinEvaluation` = rule 9 output: `periods[{index, start, end, completed, status: under|on_plan|over}]`, `proposal {direction: down|up, rhythmMin, rhythmMax (1–7), previewTargets[9] {area, setsPer14d}} | null`, `nextCheckinDate`.
9. **Requests.** `SuggestRequest = {sessionInput, tz}`. The server supplies `now`. `GET /balance?tz=…` (required). `FinishRequest = {endedAt, effortRating (optional, 1–5, D-0030), tz}`. Finish is idempotent: a repeat returns 200 and the summary for the stored `ended_at`, and a later `endedAt` overwrites it (last write wins, NFR-SYNC-3). `SessionSummary = {sessionId, startedAt, endedAt, durationS, timeBudgetMin, withinBudget, exerciseCount, hardSets, weightedSetsByArea (9 keys), balance BalanceResult}`, with `withinBudget = durationS ≤ timeBudgetMin × 60 + 120` (the same boundary as `analytics.finished_within_budget`). Running over is a valid 200, not an error.
10. **packages/shared.** `src/api.gen.ts` is generated from `api/openapi.yaml` by `openapi-typescript` (script `gen:api`). `src/database.gen.ts` comes from `supabase gen types typescript --local` (script `gen:db`, CLI 2.118.0). Both are committed. `src/index.ts` re-exports named aliases, and it overrides `sessions.plan` as `SessionPlan | null`. The package has no runtime dependency except the validator it uses for `parseSessionPlan` (Ajv, JSON Schema 2020-12). The engine keeps its own `types.ts` until it adopts these (D-0034 §1: the engine adapts). `packages/shared` never imports `@workoutlab/engine`, which avoids a cycle.
11. **priority_areas.** Migration 3 changes `profiles_priority_areas_valid` so a non-empty array must also have `array_lower(priority_areas, 1) = 1`. The existing checks stay. **Not** in migration 3: a "timed ⇒ `default_duration_s` not null" check on `exercises`. The content validator enforces it instead, so a seed from an older library can't fail `supabase db reset`.
12. **Split and the placeholder marker (TR-0015, added by triage 2026-09-28).** When T-0102 is split, the `T-0102` board row stays as the parent. Its status is `split → T-0102a, T-0102b`, and the first word is never `done` while either child is open. `T-0102a` and `T-0102b` are added as rows. `packages/shared/test/index.test.ts` keeps `@placeholder T-0102`, which the D-0023 §4 checker accepts because the id is on the board and not done. No lane retags it. T-0102a deletes it (AC14). The parent is marked `done` after both children are done.

## Consequences
- data (T-0102a/b): implements points 1–11. `docs/data-model.md` describes the new check and points `sessions.plan` at `SessionPlan` v1.
- backend (T-0203): implements the three paths, the error envelope and `requestId`, and returns 422 `profile_missing` before calling the engine.
- engine (T-0200/T-0201/T-0202/T-0204/T-0205): output shapes follow points 6–8. The engine replaces its own types with imports from `@workoutlab/shared` in a follow-up.
- content (T-0103a/b): the validator requires `default_duration_s` when `timed` is true.
- infra: CI regenerates `database.gen.ts` in the supabase job and fails on drift.
- orchestrator / product (§12): the board keeps `T-0102` as the parent row. The ticket's "Placeholder marker" paragraph drops the retag.

## Revisit when
- An endpoint is needed for check-in, swaps or the time check (for example a server-side notification).
- `SessionPlan` needs a v2. `parseSessionPlan` then gains a migration step, and old rows must still parse.
- T-0202 needs more than `hardSetCount` per session, or the engine field names differ from these.
- Clients need a 403 distinct from 404, or problem+json for third-party use.
