## Context
Checking the four tickets against `main` at `d84ba81` (T-0470 and T-0479 merged) leaves these
open points. Each one changes what a test asserts.

- **T-0471, UF-02 pins.** The stub says one UF-02 test changes. Two do. `features/UF-02/__tests__/source.test.ts`
  pins `todayCheckinSlot` to `null`, and it also says "no file in features/UF-02 imports
  features/UF-11". That second test's regex catches the dynamic `import("../UF-11/index.js")`
  that `slots.tsx` needs (its own CONTRAST test proves it).
- **T-0471, Plan goes stale after Accept.** `PlanBody` reads the cache once per mount
  (`use-plan-data.ts`). If the card is mounted above it, a successful Accept leaves "3–4 per week"
  and the old targets on screen right under a card that just changed them. That's a silent
  mismatch (principle 4). Fixing it means adding a prop to the card and remounting the body. That's
  a second change on top of the mount ticket (D-0157 §7).
- **T-0471, other e2e specs.** Most e2e profiles have `onboarded_at` 2026-09-01 (or earlier) and
  few or no sets, and the specs run on the real clock. So once the slot is set, the card (a
  step-down proposal) shows on `/` in almost every signed-in spec, and more specs qualify as the
  date moves on. `mockSupabaseData` and `mockSupabaseEmptyReads` answer `plan_checkins*` for every
  method, so the first-shown insert gets an answer. But some spec may set up its own routes, and
  no ticket says what the build may do when that spec goes red.
- **T-0346.** D-0081 §5 says "the draft is initialised once, from the first read that finds the
  routine. A later refresh never overwrites it." Combined with "no refresh when the cache has
  the id", this means a deep link on a device with a stale cache shows the old routine. Save then
  overwrites another device's newer edit (last write wins). Separately, when `routineId` changes in
  place, `loadFailed` stays `true` from the previous id.
- **T-0354.** UF-10.2's names map starts empty, so each contributor row shows the raw
  `exerciseId` until `loadLibrary()` resolves.

## Decision
1. **T-0471 changes exactly two UF-02 tests in `source.test.ts`.** (a) "todayCheckinSlot is null"
   becomes "todayCheckinSlot lazily loads CheckinCard from features/UF-11/index.js". (b) "no file
   in features/UF-02 imports features/UF-11" skips `slots.tsx` only, and a new assertion in the
   same `describe` pins `slots.tsx`: it has exactly one UF-11 reference, it is the dynamic
   `import("../UF-11/index.js")`, and it has no static or side-effect UF-11 import. The
   import-ban CONTRAST test stays as it is.
2. **The Plan re-read after Accept or Keep becomes its own ticket, T-0481** (web-feature:UF-11,
   after T-0471). `CheckinCard` gets an optional `onAnswered?: () => void`. The card calls it
   once, after a successful Accept or Keep and after that write's `refreshAll` settles
   (resolved or rejected). It is never called for a failed write. UF-11.2 passes a callback that
   remounts `PlanBody` (a `key` bump), so the body re-reads the cache. Today passes nothing (the
   slot takes no props). Today keeping its pre-Accept map and suggestion until the next mount is
   accepted for v1. That needs a UF-02 change, which is the board row T-0482 (todo, ungroomed).
3. **e2e fallout from the mount is fixed in the shared mock, nowhere else.** T-0471 runs the whole
   web e2e (`slots.tsx` sits outside the UF-11 folder, D-0158). Suppose a spec outside the grant
   fails only because the card now shows: an unclaimed `plan_checkins` request, or a backstop hit.
   Then the build may change `tests/e2e/fixtures/supabase-mock.ts`, and only its `plan_checkins`
   handling. Any other failure in a spec it doesn't own is a `needs-triage`, never a spec edit.
   T-0471's own e2e asserts nothing that depends on the date. `UF11_FIXTURES` has no sets, so on
   any day it proposes a step down from 3–4.
4. **UF-07.1 refreshes a cached routine on mount (amends D-0081 §5).** For `/plan/routines/:id`
   where the first cache read finds the id:
   - The form renders from that read at once, as it does today.
   - One `refreshRoutines()` starts, capped at 3 s (D-0071 §8). It starts only while online and
     `useAuth().status === "signed-in"`. It runs at most once per mount, and it also starts on a
     `stale` → `signed-in` change during the mount (D-0113 §1–§3). `stale` and `signed-out` sessions
     get no refresh.
   - When the refresh resolves, the editor reads `loadRoutines()` again. If the draft is
     **untouched** (name equals the loaded name, and the item id list equals the loaded list in
     order), the draft and the loaded snapshot are both replaced by the fresh row. If the draft
     is **touched**, it stays as it is, and so does the loaded snapshot. Server-wins happens at
     Save (NFR-SYNC-3), as before.
   - If the fresh read no longer has the id: an untouched draft redirects to `/plan` (replace),
     as an unknown id does. A touched draft stays.
   - A refresh that rejects, or hits the cap, changes nothing.
   - The unknown-id path (D-0081 §5's first half) is unchanged, and its refresh counts as the
     mount's one refresh.
   - When `routineId` changes in place, the effect resets `loadFailed`, `ready` and the draft
     before the new read.
5. **UF-10.2 holds its contributor rows until the names read settles.** The heading renders at
   once. With `area.contributors.length === 0`, the empty line renders at once, since no names are
   needed. Otherwise the `<ul>` renders only after `loadLibrary()` has resolved or rejected. If it
   rejected, rows fall back to the id (D-0104 / D-0115 §2, unchanged). With an `exerciseNames`
   override supplied, the list renders on the first render.
6. **T-0353's keyboard proof uses real Tab presses only.** From a fresh load of `/balance`, the
   test presses Tab at most 40 times until the C-01 hamstrings button has focus. It calls no
   `locator.focus()` on that path and fails if it never gets there. A balance row's
   `boundingBox()` is at least 44 × 44.
7. **No other split is needed.** T-0471 (about ⅓ day after §2), T-0481 (about ¼ day), T-0346
   (about ⅓ day), T-0353 (about ¼ day) and T-0354 (about ¼ day) are each under D-0157 §7's half
   day.

## Consequences
- T-0471's ticket is amended (§1, §3). T-0481 and T-0482 are new board rows.
- T-0346 moves from `product`/wl-spec to `web-feature:UF-07`/wl-build-web with a ticket file.
- T-0353 and T-0354 share the UF-10 lane but no files (an e2e spec versus `index.tsx` plus a
  unit test). Run them one after the other in either order.
- D-0081 §5's "a later refresh never overwrites it" now holds only for a touched draft.

## Revisit when

  focused a field but not typed yet.
- Today needs to reflect an Accept at once (T-0482).
- A third spec needs a `plan_checkins` change in the shared mock. At that point, give the mock an
  explicit check-in-card switch instead.
