## Context
The board had no `ready` ticket. T-0481 (UF-11) is in build, and T-0482 (UF-02) waits on it.
The orchestrator asked for 2 or 3 self-contained `todo` tickets outside UF-11 and UF-02, in lanes
that don't overlap each other, so builders can run them in parallel once T-0481 lands.

Candidates checked against main `b99a184`:
- **T-0343** (UF-10). Dep T-0307a is `done`. `useResult` pins `now` once per mount on purpose
  (the T-0307a render-loop regression), so a screen left open past midnight keeps yesterday's
  window.
- **T-0472** and **T-0473** (both UF-03). Dep T-0457 is `done` (board-done). D-0164 §1 allows one
  UF-03 ticket at a time. T-0473 is a single missing vitest in the same file T-0472 touches.
- **T-0443** (web-shell). Dep T-0424 is `done`. Two `document.body.innerHTML =` resets remain
  (UF-01 `keyboard.test.ts:7`, UF-08 `suggested-actions.test.tsx:418`). Neither lane has
  anything in flight.

## Decision
1. **T-0343 → ready.**
   - A mounted UF-10.1/.2 with no `now` prop checks the local day in its `timeZone` every 60 s,
     and at once on `visibilitychange` to visible. Background tabs throttle timers, so the
     interval alone could be hours late for a phone picked up in the morning.
   - Only a changed day sets a new `now`. `useBalance`'s existing cache-read effect then
     recomputes.
   - No second `refreshAll` at the rollover. D-0113 §2's once-per-mount rule stands, because
     midnight brings no new server data.
   - The `now` prop seam stays fixed.
   - Today and Plan are not covered. They'd get their own tickets if anyone reports the same
     issue there.
2. **T-0472 → ready, and T-0473 is folded into it.**
   - Unchecking a logged row above the plan keeps the row, unchecked, with the values it was
     logged with, rendered by the same element, so focus stays on its toggle.
   - That makes the behaviour after a reload match the behaviour within one mount, which
     D-0142 §3 asks for ("checked, edited and unchecked exactly as T-0417's rows are"). It also
     makes a mis-tap undoable in one tap.
   - Moving focus to "+ Add set" was rejected: the row would still vanish and the values would
     have to be typed again.
   - T-0473's timed-focus test becomes T-0472 AC-5. It's the same file and lane, and keeping a
     separate ticket would only queue it behind T-0472.
3. **T-0443 → ready.**
   - Replace both resets, then add a web-shell source test that walks all of `apps/web/src` and
     bans `/document\.body\.innerHTML\s*=(?!=)/`.
   - Not an ESLint `no-restricted-syntax` rule: flat config replaces, not merges, a rule set in a
     later block, and T-0313's planned dynamic-`import()` ban will probably use the same rule on
     feature files.
   - UF-09's own T-0424 guard stays as it is.
4. **Lanes.** UF-10, UF-03 and web-shell. T-0443's two listed extras are test files in UF-01 and
   UF-08. None touch `features/UF-11/**` or `features/UF-02/**`, and no two share a file, so all
   three can run in parallel with each other and with T-0481/T-0482.
