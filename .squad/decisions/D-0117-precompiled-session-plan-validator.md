## Context
TR-0036. `parseSessionPlan` (`packages/shared/src/session-plan.ts`) compiles `SESSION_PLAN_SCHEMA` at first call with `new Ajv2020(...).compile(...)`. Ajv compiles through `new Function`. The PWA's CSP (`apps/web/vite.config.ts`, pinned by `apps/web/build.test.ts` "AC-A10 CSP … no unsafe-eval") is `script-src 'self'`. In the built app the compile throws `EvalError`, `parseSessionPlan` swallows it and returns `{ok: false, error: "invalid"}`, so every real session row reads as an invalid plan and UF-09 focus mode can never start (T-0304a e2e "AC-7 the chrome on a seeded session"). Vitest/jsdom has no CSP, so unit tests can't see it. D-0043's own Consequences predicted this and named the fix.

Survey of every runtime schema compile reachable from `apps/web` on `main` (2026-10-02):
- `packages/shared/src/session-plan.ts` is the **only** runtime Ajv use in any source that ships (`packages/shared/src`, `packages/engine/src`, `apps/web/src`). Every other Ajv use is in tests (`packages/shared/test/support/spec.ts`, `data/exercises/test/helpers.ts`, `supabase/tests/functions/integration/*`).
- The row mappers (`toHistorySet`, `toLibraryExercise`, `toAreaTarget(s)`, `toEngineProfile`, `toPlanCheckin` in `packages/shared/src/mappers.ts`) are hand-written field renames with `RangeError` guards (D-0043 §5). They don't compile anything, so `lib/offline` (engine-feed, history, db, feature loaders), UF-01 save / pending-plan, UF-02, UF-08, UF-10 and UF-11 are unaffected.
- No file in `apps/web/src` on `main` calls `parseSessionPlan`. The bug is latent on `main` and first reached by T-0304a (unmerged). Every later ticket that reads `sessions.plan` in the browser would have hit it too (T-0304b to T-0304e, any history or resume screen).
- Edge Functions run on Deno with no CSP, and none calls `parseSessionPlan` today. The vendor copy (`supabase/functions/_shared/vendor/shared/session-plan.js`) still imports `ajv/dist/2020.js`, so it changes when the source changes.

## Decision
1. **Precompile, don't relax the CSP.** `packages/shared/scripts/gen-api.ts` also writes `packages/shared/src/session-plan.validate.gen.ts`: Ajv's standalone code (`ajv/dist/standalone`) for `SESSION_PLAN_SCHEMA`, ESM, with the same options as today (`strict: true`, `allErrors: false`, `allowUnionTypes: true`) plus `unicode: false` and `code: {source: true, esm: true}`. `parseSessionPlan` imports that function and calls it. The lazy compile, the `validator === null` path and the runtime `ajv/dist/2020.js` import are removed from `src/`.
   - `unicode: false` is safe because the only length keyword in the closure is `ExerciseId.minLength: 1`, and "at least one UTF-16 code unit" equals "at least one code point". It also means the generated code needs no `ajv/dist/runtime/*` import. If a later schema change makes Ajv emit a runtime import, the generator fails with a message naming it, rather than emitting it (that needs a new decision covering the Deno import map).
   - The generated file is TypeScript, so `supabase/scripts/vendor.mjs` (which compiles `src/**/*.ts` only) carries it into the vendor copy. It starts with the GENERATED header and `// @ts-nocheck`. `packages/shared/eslint.config.mjs` ignores `src/*.validate.gen.ts`. A typed wrapper in `session-plan.ts` (`(value: unknown) => boolean`) is the only consumer.
   - Drift: the existing byte-compare drift test in `packages/shared/test/` gains the new file, like `session-plan.schema.gen.ts` (D-0043 §3).
2. **Behaviour and contracts are unchanged.** D-0043 §4 semantics hold exactly (null, `unsupported_version`, `invalid`, never throws, returns the input itself). `api/openapi.yaml`, `docs/data-model.md` and `docs/engine-rules.md` don't change. The CSP and T-0300a AC-A10 stay as they are.
3. **Option 2 (`'unsafe-eval'`) is rejected.** It weakens XSS protection for the whole app to work around one validator, and it reverses a pinned test. Option 3 (hand-written check in UF-09) is rejected: a second implementation of a shared contract inside a feature lane drifts (lane separation, principle 3 spirit).
4. **Guards, so this class of bug can't come back silently.**
   - (a) **No-eval proof in Node** (`packages/shared/test/`): a child `node --disallow-code-generation-from-strings --import tsx` process (or a `node:vm` context with `codeGeneration: {strings: false}`) imports `src/index.ts` and runs `parseSessionPlan`. That flag makes `eval` and `new Function` throw `EvalError`, as the CSP does. The child accepts the AC7 v1 plan and rejects the "no startDeficits" plan. Two controls run in the same process: `new Function("return 1")` throws `EvalError`, and `new Ajv2020(...).compile(SESSION_PLAN_SCHEMA)` (the old path) throws. The second control shows the test would have caught TR-0036.
   - (b) **Source scan** (`packages/shared/test/`): no file under `packages/shared/src` imports `ajv` or `ajv/dist/*` except via the `*.gen.ts` generated file, and that one has no `import`/`require` at all.
   - (c) **Bundle scan** (`apps/web/build.test.ts`, which already builds `dist/`): no emitted JS asset contains `new Function(`, Ajv's compile error string `Error compiling schema`, or the Ajv compiler's `ajv/dist/compile` code marker. If a third-party library introduces a `new Function`, the builder raises triage. No allowlist is added silently.
   - (d) **Real-CSP browser proof** (`tests/e2e/`): Chromium loads a same-origin page carrying the CSP copied from the built `dist/index.html`, runs a browser bundle of `parseSessionPlan` and gets `ok: true` for a v1 plan. A control on the same page shows `new Function` throws `EvalError`. The end-to-end user proof is T-0304a's "AC-7 the chrome on a seeded session" row passing with its `test.fail` marker removed.
5. **Lane and ticket.** The work is T-0229, lane `data` (owns `packages/shared/**`; the generator is `packages/shared/scripts/gen-api.ts`). Listed extras: `apps/web/build.test.ts` (4c), one new spec under `tests/e2e/` (4d), and the regenerated `supabase/functions/_shared/vendor/shared/**`. The vendor copy is regenerated by running `node supabase/scripts/vendor.mjs` in the same branch, never edited by hand, so `vendor.mjs --check` stays green at merge. The `ajv/dist/2020.js` mapping in both `deno.json` files becomes unused but stays (removing it would change the T-0203b AC12 test; that cleanup is optional backend work).
6. **`ajv` stays in `packages/shared` `dependencies`** for now, so `pnpm-lock.yaml` (infra lane) doesn't change in T-0229. Moving it to `devDependencies` is an optional follow-up. It no longer reaches the web bundle either way, because nothing in `src/` imports it.
7. **T-0304a.** Its merge stays held until T-0229 is merged. Then it rebases, removes the `test.fail(true, "TR-0036: …")` marker on AC-7, and that row must pass. T-0304a needs no code change for this, because it already calls `parseSessionPlan`.

## Consequences
- The Ajv compiler (about 120 kB minified, D-0043) leaves the web bundle, which helps `check:size`.
- Every browser reader of `sessions.plan` works under the strict CSP with no change on their side.
- Changing the `SessionPlan` schema in `api/openapi.yaml` now regenerates two files (`schema.gen.ts` and `validate.gen.ts`) plus the vendor copy. The drift tests catch a missed regen.
- `parseSessionPlan` still can't tell a schema failure from "the validator couldn't run", but after this decision the second case no longer exists in shipped code.

## Revisit when
- A `SessionPlan` v2 schema needs a keyword whose standalone code imports an Ajv runtime helper (formats, unicode length, deep equal). Then decide how the Deno import map maps `ajv/dist/runtime/*`.
- Another runtime schema validator is added to `packages/shared` (it must follow this pattern).
- The CSP changes for any other reason.
