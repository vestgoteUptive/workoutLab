## Context
D-0168 wrote T-0216, T-0469, T-0470 (and T-0418 was written 2026-10-02) before their deps were
on `main`. Checking each against `main` at `f83403e` (T-0308c, T-0310d, T-0417, T-0421, T-0414
merged) leaves these open points, each of which changes what a test asserts:
- **T-0470 AC-1** expects `completed_prev: 7`. The engine lists at most one period
  (`COMPARED_PERIODS = 1`, D-0061 §2), so with the real engine the "previous listed period" never
  exists. D-0070 §6 (T-0223, on main) says `completed_prev` is null for a one-period evaluation.
- **T-0470, a second device.** The 23505 path "reads the existing row", but not what the card does
  when that row is already answered on the other device. Nor does the ticket say whether a
  successful insert refreshes the check-in cache (without it, every remount inserts again and
  hits 23505).
- **T-0418, focus.** Leaving the rest view (Skip, Back to list) or the swap sheet (Apply, Cancel)
  unmounts the node that had focus. The ticket doesn't say where focus goes.
- **T-0418, time zone.** `SwapSheet` takes an optional `timeZone`; the List view doesn't pass one.
- **T-0418, phases.** The host starts a rest only from `set`, `confirm`, `rest` and `timed`
  (`REST_STARTABLE`, `features/UF-09/machine.ts`). Opening the List view from a pause taken in
  `getReady` or the warm-up resumes into that phase, so a set checked there starts no rest.
- **T-0469.** The ticket names the user `u@test.local`; the e2e session helper signs in
  `ada@example.com` (id `11111111-…`). `mockSupabaseData` answers every `sessions*` and
  `session_sets*` read with `[]`, so the export would hold 0 sets. A spec route on
  `session_sets*` registered later would also shadow `session_sets_live*` (the history read).
- **T-0216** names `AccountSettings.tsx`; the file on main is `AccountSettingsBody.tsx`.
- **Parallel UF-11 tickets.** T-0216 and T-0470 both add strings to `flows/uf-11.ts` and both
  need supabase spies from `__tests__/test-helpers.tsx`.

## Decision
1. **T-0470 insert values.** `completed_prev` = the `completed` of the entry before the last one in
   `evaluation.periods` when there is one, else `null`. With the real engine (one period) it is
   always `null`; a two-entry stub pins the other branch (`completed_prev: 4`).
2. **T-0470 cache and second device.**
   - After a successful insert, `refreshCheckins()` runs once (a rejection is ignored), so the next
     mount reads the row from the cache and makes no insert.
   - On a `23505`, the card selects the row for this `period_index`. If its `answer` is `null`, the
     card stays as it is (no write, no alert). If its `answer` is set (the other device answered),
     the card hides and `refreshAll()` runs once (its rejection ignored). Either way no alert and no
     `console.error`. A failed select keeps the card, silently (the next mount retries).
3. **T-0418/T-0478 focus.**
   - After Swap Apply or Cancel (T-0478): focus on the "Swap" button of the same card (the sheet's own
     opener-restore can't find a re-mounted node; D-0168 §2 did the same on UF-08.2).
   - After "Back to list": focus on the rest bar.
   - After Skip, or when the rest ends while the rest view is open (the view closes): focus on the
     first unchecked row's checkbox of the current card, else on "Finish".
4. **T-0418/T-0478 ctx and time zone.** The List view passes `timeZone: ctx.timeZone` to `SwapSheet`. Its own
   `ListViewCtx` gains the read fields and actions it now uses (`workout`, `timeZone`, `rest`,
   `startRest`, `adjustRest`, `skipRest`, `replaceItem`), so `tsc` still proves `FocusSession` fits
   (D-0142 §5); no `features/UF-09` file changes.
5. **T-0418 phases.** T-0418 ships with the host's `REST_STARTABLE` as it is: the List view calls
   `ctx.startRest` and shows a bar only when `ctx.rest` is non-null. Letting the host start a rest
   from `getReady`/`warmup` under an open List view is UF-09 lane work: follow-up **T-0477**.
6. **T-0469 fixtures.**
   - The signed-in user is the e2e session helper's user (`ada@example.com`, id `11111111-…`); V is
     any other uuid.
   - The spec registers, **after** `mockSupabaseData`, routes matched by a predicate on the exact
     pathname (`/rest/v1/sessions`, `/rest/v1/session_sets`, GET only), never a `session_sets*`
     glob, answering 2 sessions and 3 sets. AC-1 also asserts the history read
     (`session_sets_live`) was still answered by the base mock (its route was hit).
   - Fixture data lives in the spec file (in-spec helpers, D-0071 §10) unless it passes ~60 lines;
     a new `tests/e2e/fixtures/uf-11-account.ts` is allowed but then the whole web e2e runs once
     (D-0158).
7. **T-0216 file.** The section is a component of its own (`EquipmentSection.tsx`) rendered by
   `AccountSettingsBody.tsx` between the "Signed in as" line (absent when no email is stored) and
   the "Your data" section.
8. **Parallel UF-11 tickets keep to their own files.**
   - Strings: T-0470 adds keys at the end of `checkin: {…}`; T-0216 adds `equipment: {…}` as the
     last key of `account: {…}`. Neither reorders existing keys.
   - Test helpers: each ticket puts new helpers in a new file of its own
     (`__tests__/equipment-helpers.tsx`, `__tests__/checkin-writes-helpers.tsx`) and only imports
     from `test-helpers.tsx` and `fixtures.ts`, never edits them.
   - So T-0216, T-0469 and T-0470 may run in parallel; T-0471 still waits for T-0470.
9. **T-0418 splits in two** (D-0157 §7: §3–§4 took it from 6 to 8 ACs, past half a day).
   - **T-0418** keeps the rest bar, the rest view UF-03.2 and the rest focus targets.
   - **T-0478** (new) takes the Swap button, rows after a swap, `timeZone` and the Swap focus
     target. It runs after T-0418: both edit `ListView.tsx`.
10. **DoD wording.** All four tickets' DoD now names `scripts/locked.sh` (D-0169) instead of the old
   `flock` line and the cached gate (D-0158) instead of `--force`.
