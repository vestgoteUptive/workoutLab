## Context
The four tickets were checked against `main` after T-0304d, T-0427, T-0429 and T-0431 merged, with
T-0423 merging. That check found these open points:

1. **The UF-09.6 ring (T-0304g).** D-0119 §10 and the T-0304g AC-5 name rings on UF-09.2, .5, .6
   and .7. UF-09.6 (`next-exercise.tsx`) has no ring, only a `role="timer"` text. UF-09.2 and
   UF-09.7 use `ring.tsx`. UF-09.5 (`rest.tsx`) draws its own copy of the ring.
2. **No `matchMedia` (T-0304g).** D-0119 §10 says nothing about a browser without `matchMedia`.
   C-01's `components/body-map/use-reduced-motion.ts` treats that as "reduce", but UF-09 may not
   import `components/body-map` (AC-D11).
3. **The deep-import lint (T-0304g AC-1).** `app/__tests__/import-bans.test.ts` AC-10 already
   proves that `features/UF-09` deep-importing `UF-08/focus-prefs.js` is an error, and that the
   index import is not.
4. **The 501 backstop is silent (T-0436).** D-0086 §2 counts a `mockSupabaseRest` /
   `mockSupabaseAuth` 501 as a claim. `consoleGuard` exempts Chromium's `Failed to load resource:`
   line. So a spec that forgot a data mock gets a 501, passes both guards, and only a behaviour
   assertion might notice (T-0427 review and QA).
5. **A reused server on :4173 (T-0440).** `reuseExistingServer: !process.env.CI` makes a local run
   quietly test another worktree's build (53 false reds on main, 2026-10-02).
6. **A full `/tmp` (T-0440).** On this machine `/tmp` is a RAM tmpfs. At about 80 % full, Chromium
   fails every page with `ERR_INSUFFICIENT_RESOURCES` or `Target crashed` (84 false reds,
   2026-10-02). The workaround, `TMPDIR=$HOME/.cache/wl-pw-tmp`, lives only in `state.md` and
   `_common.md`.

## Decision
1. **Reduced motion covers the rings that exist (T-0304g; amends D-0119 §10).** The rule applies to
   the ring fill on UF-09.2, UF-09.5 and UF-09.7. UF-09.6 has no ring, so its AC is "its
   `role="timer"` text still changes each second", with no transition to check. `rest.tsx` may
   switch to `ring.tsx` or apply the same inline style. Either is fine, as long as the UF-09.5
   tests stay green unedited.
2. **No `matchMedia` counts as reduce (T-0304g).** With `window.matchMedia` missing, the ring's
   `style.transition` is `"none"`, the same safe default C-01 uses. UF-09 has its own few-line read
   in `features/UF-09/`. It doesn't import `components/body-map`.
3. **The deep-import lint is already pinned (T-0304g).** T-0304g keeps `import-bans.test.ts`
   AC-10 green and doesn't add a second copy of that test.
4. **A backstop hit is reported (T-0436; amends D-0086 §2).**
   - `mockSupabaseRest` and `mockSupabaseAuth` mark their 501 with a response header
     (`x-wl-e2e-backstop: rest` or `auth`). `installSupabaseGuard` records every response on the
     context that carries the header as `"<METHOD> <URL>"` in a new list, `backstopHits()`. If the
     builder measures that a route-fulfilled response's headers can't be seen from a context
     listener, a registry in `supabase-mock.ts` keyed by `page.context()` does the same job. The
     build log says which was used. Its
     `assertClean()` fails on either list. The message names the request and points at the mock
     helpers.
   - A test that means to hit the backstop (an error-path test, or a guard self-test) acknowledges
     it with `supabaseGuard.allowBackstop(/pattern/)`. The rules are the T-0430 rules for
     `consoleGuard.allow`: no `g` or `y` flag, and a `T-NNNN` in the comment block directly above
     the call. That is the ticket whose test wants the hit, or the follow-up that will mock it.
     The allow lasts for one test only. The preferred fix is still a real mock (`200 []` for a read, an
     accepted no-op for a write).
   - "Claimed" (D-0086 §2) still means kept off the network. The 501 catch-alls stay, and the
     guard's own last-resort route and its `requestfailed` detector are unchanged.
   - `consoleGuard`'s `Failed to load resource:` exemption stays. Network behaviour belongs to
     `supabaseGuard`, and now it reports backstop hits.
   - `fixture-guard.spec.ts` "a request claimed by the 501 backstop is not reported" becomes its
     inverse, "… is reported, and allowBackstop exempts it". That is the change this decision
     names, not a weakened test.
5. **Local e2e never reuses a server (T-0440).** `webServer.reuseExistingServer` is `false`
   locally as well as in CI. When anything already answers on `http://localhost:4173`, Playwright
   stops before any test with its "is already used" error. That error is the loud failure.
   - There is no served-build-id check. With the machine-wide test lock, a port that is in use
     always means a stray or unlocked run, and the right response is to stop.
   - The cost is a fresh build on every local run, which is what `CI=1` runs already pay.
6. **A nearly full tmpfs fails at config load (T-0440).** The config doesn't set `TMPDIR`. That
   path is machine-specific, and CI runners have a disk-backed `/tmp`.
   - At load, `playwright.config.ts` calls a pure check in `tests/e2e/fixtures/preflight.ts` on
     `fs.statfsSync(os.tmpdir())`. If the filesystem is a tmpfs (statfs `type` `0x01021994`) and
     at least 80 % used, the check throws one error. The error names the directory, the percentage
     and the fix, `TMPDIR=$HOME/.cache/wl-pw-tmp` (create it first).
   - A disk-backed tmp, or a statfs that throws, passes silently.
   - The config's header comment also documents the trap.

## Consequences
- T-0304g encodes §1–§3, T-0436 encodes §4, and T-0440 encodes §5–§6. T-0416 needs no new rule:
  its refresh only moves its deps behind T-0422 and T-0433.
- No contract change. Everything here is device-local UI or e2e test infrastructure.
- T-0437 (whether to exempt Chromium's `sw.js` fetch line) and T-0432 (every spec imports the
  guarded fixture) both touch the files T-0436 edits, so they run after it.

## Revisit when
- A real device or browser shows `matchMedia` missing while the user wants motion.
- The backstop acknowledgements pile up in product specs. Then default unmocked reads to `200 []`
  (the T-0327 / D-0072 "Revisit when" option) instead.
- A developer wants a fast local loop that reuses a server. Then add a build-id check behind an
  explicit opt-in env var, never as the default.
- The 80 % tmpfs threshold gives a false stop, or Chromium still crashes below it.
