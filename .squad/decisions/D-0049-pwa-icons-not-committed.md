## Context
D-0045 §8 says the manifest/theme colours and the icons are generated from
`@workoutlab/design-tokens` at build time, and that `public/` and `index.html` hold no
colour values so `wl-check-colours .` stays green. `apps/web/scripts/gen-icons.mjs` writes
the three PNGs to `apps/web/public/icons/` as a `--stage=pre` step of the `build` script,
before `vite build` runs, so `vite-plugin-pwa`'s workbox `globPatterns` (which only see files
that already exist in `dist/` when it closes the bundle) can find and precache them; the
favicon SVG is written straight to `dist/` in a `--stage=post` step, since it never needs
precaching. The budget-capped run left the three generated PNGs staged in git as tracked
files under `apps/web/public/icons/`.

PNGs aren't scanned by `wl-check-colours` (binary, and not in its text `EXTENSIONS` set), so
committing them wouldn't have failed AC-A4. But they are pure build output — deterministic
from `tokens.json` — and the repo's existing convention (`packages/design-tokens/dist/`,
`apps/web/dist/`) is that generated output is gitignored, not committed. Committing them
would also mean every future token colour change needs a manual regenerate-and-commit step
that's easy to forget, and diffs on every rebuild if resvg's output isn't byte-stable across
machines.

## Decision
`apps/web/public/icons/` is added to the root `.gitignore`. The three PNGs are untracked
(`git rm --cached`). They're regenerated by the `--stage=pre` step of `pnpm --filter
@workoutlab/web build` (and can be regenerated standalone via `node scripts/gen-icons.mjs`)
before every build, so they always reflect the current tokens. No test depends on the files
being present in git: `gen-icons.test.ts` writes to a temp dir, and the AC-A3/AC-A5 checks
run against a fresh `dist/` build.

## Consequences
- A clean checkout has no `apps/web/public/icons/*.png` until `pnpm --filter @workoutlab/web
  build` (or `dev`, if a future ticket wires icons into `index.html`) runs the pre-step.
- CI must run the `build` script (not just `vite build`) so the icons exist before
  `check:size`/e2e/Lighthouse steps that read `dist/`; the existing `package.json` `build`
  script already does this.
