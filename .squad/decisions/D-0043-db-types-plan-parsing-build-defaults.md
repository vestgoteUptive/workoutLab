## Context
T-0102 AC15–AC20 need `packages/shared/src/database.gen.ts` as the output of `supabase gen types typescript --local` (CLI 2.118.0) after migrations 1–3. That needs a running local stack. Docker on this host can't pull the Supabase images, and the Supabase CLI isn't installed. AC17 needs `parseSessionPlan()` to validate `sessions.plan` at runtime, on the device and offline, but `api/openapi.yaml` isn't available in a browser bundle. The ticket doesn't say how `sessions.plan` is overridden, how strict the mappers are, or how `gen:api` runs on Node 22 versions without type stripping. D-0039 §6 relied on `prettier` being hoisted from the workspace root.

## Decision
1. **`database.gen.ts` is written by hand to match the CLI output.** It follows the postgres-meta TypeScript template that `supabase gen types` uses: a `Json` type; `__InternalSupabase.PostgrestVersion`; `graphql_public` and `public` (the schemas in `supabase/config.toml` `[api].schemas`); tables and columns sorted alphabetically; `Insert` marks a column optional when it is nullable or has a default; `Update` makes every column optional; `Relationships` list only FKs inside `public` (the `auth.users` FKs are left out), using Postgres's default `<table>_<column>_fkey` names or the named composite FKs; the `session_sets_live` view has every column `| null` and inherits the `session_sets` relationships; plus the `Tables`/`TablesInsert`/`TablesUpdate`/`Enums`/`CompositeTypes`/`Constants` helpers. The file is formatted with the repo's Prettier config, and `gen:db` runs Prettier after the CLI too. The columns come from migrations 1–3 and `docs/data-model.md`. The AC15 test parses `database.gen.ts` with the TypeScript compiler API and checks it against every column table in the doc: name, TS type and nullability. When a stack is available, the first `pnpm --filter @workoutlab/shared gen:db` run replaces the file. Any diff (for example the `PostgrestVersion` string, `13.0.5` here) is cosmetic, as long as AC15 stays green.
2. **`sessions.plan` override.** `@workoutlab/shared` exports `Database`: the generated type with `public.Tables.sessions` `Row`/`Insert`/`Update` `plan` replaced by `SessionPlan | null` (optional on Insert and Update). It also exports its own `Tables`, `TablesInsert` and `TablesUpdate` over that `Database`, for the `public` schema only. The generated one is exported as `GeneratedDatabase`. Clients use `createClient<Database>()`.
3. **Runtime schema for `parseSessionPlan`.** `scripts/gen-api.ts` also writes `src/session-plan.schema.gen.ts`. That file holds the `SessionPlan` component plus the components it references, as one JSON Schema 2020-12 document. OpenAPI annotations (`description`, `example(s)`, `discriminator`, `x-*`) are stripped, and refs are rewritten to `$defs`. A drift test compares it byte for byte. `ajv` becomes a runtime `dependency` of `packages/shared`. The validator is compiled lazily on the first call. `ajv-formats` isn't needed because the closure has no `format`.
4. **`parseSessionPlan(json)` semantics.** `null` → `{ok: true, plan: null}`. An object whose `version` is a number other than 1 → `unsupported_version`. Anything else that fails the schema → `invalid`, including strings (they aren't JSON-parsed, because supabase-js returns jsonb already decoded), arrays, `undefined`, and objects with a throwing getter. A successful parse returns the input value itself, not a copy.
5. **Mappers.** They rename fields only, with no filtering or clock. `toHistorySet(row, {pending?})` sets `pending` only when the caller passes it. `toAreaTargets(rows)` sorts by the fixed area order. For DB text columns that the engine types as literal unions, the mappers throw `RangeError` on a value outside the union. DB checks make that unreachable, so it only signals schema drift. The same applies to an `exercise_areas.weight` other than 1 or 0.5. D-0041 §2 is noted in `src/mappers.ts`: `evaluateCheckin` reads only `PlanCheckin.answeredAt`, and `CheckinProfile` is a subset of `EngineProfile`, so the mapped values can be passed straight in.
6. **Tooling (amends D-0039 §6).** `gen:api` runs through `tsx` (a new devDependency of `packages/shared`), so it works on every Node 22, including those before 22.6, which have no type stripping. `prettier` is now a direct devDependency of `packages/shared` (`^3.4.2`, the same range as the root). The package no longer relies on pnpm's default `*prettier*` public hoisting. `D-0040 §4`'s `WorkoutItem.backoff.weightKg` nullable was already in the v1 spec (T-0102a), so there is no schema change.

## Consequences
- AC15 checks the committed file against the doc, not against a live database. The real-stack proof is the CI `supabase db reset && supabase test db` run on the draft PR (AC20). A CI drift job for `database.gen.ts` stays an infra follow-up (T-0102 scope "Out").
- `ajv` ships in the web bundle, roughly 120 kB minified before gzip. Ajv compiles with `new Function`, so a CSP without `'unsafe-eval'` would break `parseSessionPlan`. If the PWA adopts a strict CSP, switch to Ajv standalone code generated by `gen:api`.

## Revisit when
- A stack is available to run `gen:db`. If the diff goes beyond `PostgrestVersion`, fix the file and this decision.
- The PWA sets a CSP without `'unsafe-eval'`, or bundle size becomes an issue.
