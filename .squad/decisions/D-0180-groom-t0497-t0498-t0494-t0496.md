## Context
The board had no `ready` rows. Six candidates were checked on `main` at `72f984c`:
- T-0497 (backend): T-0210 documented that `loadSessionSets` relies on RLS for a unique
  `client_id` order key and that a service-role client "must add" the `user_id` filter. T-0209
  and T-0218 edit the same files but are `todo`, not `doing`.
- T-0498 (landing): `Layout.astro` imports the generated `tokens.css`; landing's vitest global
  setup runs `astro build`, so a fresh worktree fails outside turbo. Web fixed this with a
  `pretest` (`apps/web/ensure-tokens-css.mjs`), which a direct `npx vitest run` skips.
- T-0494 (UF-03): `SwapLoadBoundary`'s failure state has no axe check.
- T-0496 (infra): the T-0490 audit regex has no mechanical guard. Only T-0490's own file matches
  it on `main`.
- T-0481 already has a full ticket file (2026-10-03, D-0174 §2) and only waits for T-0471.
- T-0482 is marked ungroomed. It needs either a slot callback or a cache-change signal, and both
  depend on how T-0471 (still `doing`, in rework) leaves the slot and `CheckinCard` API.

## Decision
1. **T-0497.** Add `.eq("user_id", ctx.userId)` to `loadSessionSets`, before the `session_id`
   filter. Rewrite the JSDoc to say the function now scopes itself, with RLS and
   `session_sets_session_fk` as further guards. Prove it with a filtering fake client (two users
   sharing a `client_id` on one session). No schema, RLS or API change.
2. **T-0498.** Landing's `test/global-setup.ts` spawns `apps/web/ensure-tokens-css.mjs` before its
   Astro builds and throws a named error on failure. Use global setup, not a `pretest`, because
   agents run landing tests with a direct `npx vitest run` (D-0158 small tier), which skips
   `pretest`. Landing reads web's script unchanged, without copying it. Moving the script into
   `packages/design-tokens` as a shared bin is a later design-lane follow-up.
3. **T-0494.** Test-only: axe on the failure state (first failure and after a failed retry), and
   console hygiene on first failure. Change `SwapLoadBoundary` markup only if axe finds a real
   violation. Focus on entering the failure state is out of scope.
4. **T-0496.** New hygiene check `ticket-filter-chain` in the D-0023 family, scanning
   `docs/tickets/*.md` (top level, not `log/**`). It uses T-0490's regex plus a one-line-join for
   wrapped commands. Only T-0490's own file is exempt, and the exemption is by path, with no
   inline opt-out.
5. **T-0481 and T-0482.** T-0481's existing file stands. It becomes `ready` when T-0471 is done.
   Re-read it against the merged API first. T-0482 is groomed only after T-0471 merges.

## Consequences
- T-0497 must not run alongside T-0209 or T-0218.
- T-0494 is the only UF-03 work. T-0495 (web-shell, `lazy-retry.ts`) doesn't touch its files.
- After T-0496 lands, a ticket that quotes the bad form has to describe it in words.

## Revisit when

  same way (§1).
- The tokens CSS gets a third consumer: do the shared-bin follow-up (§2).
