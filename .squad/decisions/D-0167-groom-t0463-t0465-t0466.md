## Context
- **T-0466.** D-0074 makes every ticket list its own `docs/tickets/T-NNNN-*.md` under `## Paths
  you may change`, or its build, QA and accept logs fail `check-lane-paths`. T-0356, T-0307b and
  T-0308a all tripped on a missing self-grant. Each fix was an orchestrator commit to `main`.
- **T-0463.** T-0451 gave the UF-05 swap seam an in-page retry (D-0162 §3). The how-to (UF-04)
  and List view (UF-03.1) seams still use a plain `lazy()`, so a rejected chunk stays failed until
  a reload. QA fault F3 (`swapSheet.reset()` on every `SwapOverlay` render) survived every test.
  The retry button needs a label. `flows/uf-03.ts` is being edited by T-0417 (in flight), and the
  seam placeholder is UF-09's own chrome.
- **T-0465.** T-0459's `RouteBoundary` is keyed by the route pattern. D-0164 §7 said no reset on a
  param change is needed, because a failed `lazy()` stays failed. That holds for a chunk failure,
  but not for a render error: one bad `/library/:exerciseId` keeps the fallback for every other
  id until a reload. Focus also stays where it was when the fallback mounts.

## Decision
1. **A ticket always owns its own ticket file (amends D-0074 §4).** `check-lane-paths` allows a
   changed path when it is a direct child of `docs/tickets/`, its basename starts with
   `<ticketId>-`, and it ends in `.md`: the same match `readTicketAtBase` uses. Nothing else is
   implied. Not `docs/tickets/log/**`, not another ticket's file, not `T-0466a-*.md` for `T-0466`,
   and no new grants: grants are still read from the base (D-0074 §5). Groomers may keep listing
   the self-grant. It is harmless, and needed until T-0466 is on `main`.
2. **The how-to and List view seams retry like the swap seam (D-0162 §3).** On tap ("Try again")
   and on the next open, never automatically. The import is retried, and the overlay never closes
   by itself. The List view keeps its clocks running throughout (D-0142 §8).
3. **The label is `en.uf09.seamRetry: "Try again"`** in `lib/i18n/flows/uf-09.ts`, a listed extra
   of T-0463. The swap chrome keeps `uf05.retry`.
4. **A lazy seam is reset only when its boundary catches**, never on render. A parent re-render
   of an open overlay neither re-imports nor remounts the view (F3).
5. **RouteBoundary (amends D-0164 §7).**
   - The fallback moves focus to "Reload" when it mounts.
   - A failed boundary resets when `location.pathname` changes within the same route pattern. For
     a chunk failure, the cached rejection shows the fallback again (harmless). For a render error,
     the new id renders.
   - The boundary stays keyed by the route pattern, so a working route keeps its component
     instance across param changes. Keying the boundary on the pathname would remount every
     working detail screen on each id change, which is a behaviour change. Rejected.
   - The reset never re-runs a guard: the boundary stays inside the guard and the profile gate.

## Consequences
- T-0466 (infra) changes `.github/scripts/check-lane-paths.mjs`, its tests and its header comment.
- T-0463 (web-feature:UF-09) changes `features/UF-09/seams.tsx` and adds the string. It runs
  after T-0446, which also edits `seams.tsx`.
- T-0465 (web-shell) changes `app/RouteBoundary.tsx` and `app/App.tsx`. It starts from a `main`
  that has T-0459.

## Revisit when
- A ticket needs to edit another ticket's file as part of its build. That is still a groom grant.
- Users land on the route fallback often enough that Reload focus gets in the way, for example
  while offline with uncached chunks.
