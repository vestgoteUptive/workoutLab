## Context
Gap B7: nothing said how the app behaves offline, how conflicts resolve, how fast it must be, or how EU health-adjacent data is handled.

## Decision
Full list: `docs/specs/non-functional.md` (IDs `NFR-*`). The key points:
- **Offline:** once a session has started, UF-08.4 → UF-09.* → UF-03.3 work with no network. Sets go to an IndexedDB queue and are never dropped, not even when auth expires. Suggestions run on the device from the cached library and history (D-0001 engine in the browser).
- **Conflicts:** sets are append-only, keyed by a client-generated UUID, and the server dedupes them. For every other row the server wins (last write by server timestamp).
- **Performance:** LCP ≤ 2.5 s on a mid-range phone over 4G; initial JS ≤ 200 KB gzip; `suggest()` ≤ 50 ms for 400 sets of history; "Done set" gives feedback within 100 ms.
- **Accessibility:** WCAG 2.2 AA. Touch targets ≥ 44×44 CSS px. Coverage never relies on colour alone (D-0003).
- **i18n:** English only in v1, strings in one catalogue, kg only, dates and times through `Intl`.
- **Analytics:** no third-party analytics or trackers in v1. Product metrics are computed from our own tables.
- **Privacy:** EU region, data minimisation (no DOB, sex, body weight or heart rate), account export (JSON) and deletion in-app in v1.
- **Timers:** computed from wall-clock timestamps, so they survive the app going to the background or the screen locking.

## Consequences
T-0100 adds `client_id uuid` (unique per user) to `session_sets`. T-0300 owns the queue and persistence. T-0400 picks an EU region. The security reviewer extends privacy into `docs/security/`.

## Revisit when
First real-device test, or before public launch (GDPR review).
