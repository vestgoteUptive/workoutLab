## Context
The five board rows were checked against `main` after T-0415, T-0416, T-0422, T-0304g, T-0307b,
T-0308a, T-0436 and T-0453 merged (T-0447 merging; T-0394, T-0451 and T-0441 in flight).

1. **T-0417 is over half a day** (D-0157 §7). As groomed on 2026-10-02 it held check, edit,
   uncheck, the weight parser, pending and rejection states, "+ Add set", reload, the return to
   focus mode and the NFR-OFF-2 List view e2e. T-0416 also deferred its List view Playwright spec
   to it. The e2e alone needs a running-session seed in `uf-03-list-summary.spec.ts`, which today
   only seeds an ended one.
2. **T-0456 and T-0454** both edit `features/UF-07/EditorForm.tsx` (D-0162 Consequences), and each
   is about a quarter of a day.
3. **UF-07.1 with an unreadable cache.** When `loadRoutines()` throws, the editor stays not ready
   and renders only its `<h1>`. The route has no tab bar, so there is no way out but Back. With an
   empty library cache the picker reads `No exercises match ""`.
4. **The UF-07.1 delete dialog offline.** If the device goes offline while "Delete" has focus,
   Chromium's focus fixup drops focus to `<body>`. The dialog's Tab trap no longer sees the key.
   Also, with focus on no button (`indexOf` is -1), Shift+Tab lands on the first button, not the
   last.
5. **UF-09 device features (T-0304g review).** Speech queued before a Pause or an unmount keeps
   talking. iOS Safari speaks only after a `speak()` inside a user gesture. iOS also leaves an
   `AudioContext` in the `"interrupted"` state (after a call or Siri), which the code doesn't
   resume. A keyboard-only user never fires `pointerup`, so `onActivation` never resumes anything.
6. **The swap seam's zone (T-0422 review).** `SessionHost` takes a `timeZone` prop and resolves it
   for clock times (D-0120 §2), but `SwapSheet` falls back to the device zone because the seam
   doesn't pass it.
7. **Route chunks.** `App.tsx` has no error boundary. After a deploy, a tab left open asks for a
   chunk hash that is gone, the lazy import rejects and the whole app goes blank.

## Decision
1. **T-0417 splits into three web-feature:UF-03 tickets, built one at a time:**
   - **T-0417** UF-03.1 logging: check, edit, uncheck, the weight parser and its hint, pending and
     rejection, reload, back to focus mode. The 2026-10-02 ACs, minus "+ Add set" and the e2e.
   - **T-0457** UF-03.1 "+ Add set" (D-0142 §3), with reload of an added set. Deps: T-0417.
   - **T-0458** the UF-03.1 List view Playwright spec (NFR-OFF-2), appended to
     `tests/e2e/uf-03-list-summary.spec.ts`, with its own running-session seed in that spec (no
     fixture edit). It is the spec T-0416 deferred. Deps: T-0417. It doesn't need T-0457.
   - T-0418 (UF-03.2) keeps its dep on T-0417 and gains none.
2. **T-0456 folds into T-0454.** One branch, one EditorForm change. The T-0456 board row closes when
   T-0454 merges.
3. **UF-07.1 with an unreadable cache.**
   - When a routines read throws (the first read, or the one after the capped refresh), the editor
     shows "Couldn't read your routines on this device." (`role="alert"`) and a link "Back to Plan"
     to `/plan`, below the `<h1>`. There is no form, no automatic retry and no redirect.
   - `/plan/routines/new` reads no routines, so it never shows this state.
   - **An empty library** (a `loadLibrary()` that throws, or one with no `kind: "exercise"` row)
     makes the picker read "The exercise library isn't on this device yet. Go online, then open this
     screen again." in place of the match list, whatever the query. A non-empty library keeps
     `No exercises match "{query}"` for a query with no match.
4. **The UF-07.1 delete dialog (amends D-0162 §5).**
   - When the device goes offline with the dialog open and focus on "Delete", focus moves to
     "Keep routine" in the same commit as the disable, so it never reaches `<body>`.
   - The dialog container takes `tabIndex={-1}`. A click inside it on no button keeps focus in the
     dialog.
   - With focus on no enabled button inside the dialog, Tab goes to the first enabled button and
     Shift+Tab to the last.
5. **UF-09 device features (amends D-0119 §8).**
   - **Cancel.** With `voice` on, `speechSynthesis.cancel()` runs on the machine's unmount and on
     the first observation of a `paused` state after a state that wasn't paused. With `voice` off,
     it is never called.
   - **Prime.** With `voice` on, the first `onActivation` (a `pointerup` in the host, the event
     iOS counts as a user activation) speaks one empty utterance (`text ""`, `volume 0`), once per
     mount. With `voice` off, nothing is spoken. A `pointerdown` or `keydown` doesn't prime: iOS
     may not count a `pointerdown`, and desktop browsers, where keyboards are used, need no prime.
     The T-0304g tests' `gesture()` fires only `pointerdown`, so their speak asserts don't change.
   - **Resume.** A context in `"suspended"` **or** `"interrupted"` is resumed: before a tone, on
     `onActivation`, and on a later `onGesture` (a keyboard user's next key). A `"running"` or
     `"closed"` context is never resumed.
   - All of it stays in `features/UF-09/device.ts`, and none of it throws when an API is missing.
6. **The swap seam's zone.** `FocusSession` gains `timeZone: string`, the zone the host resolved
   (the prop, else the runtime zone). The swap overlay passes it to `SwapSheet`. `ListViewCtx` is
   unchanged (it types its own subset, D-0142 §5).
7. **An app-wide route-chunk boundary (web-shell).**
   - Each route's `<Suspense>` in `Shell` sits inside one error boundary, which in turn sits inside
     the guard and the profile gate. So a boundary reset never re-runs the `session` guard's
     mount-time decision.
   - It catches any error thrown under the route, a rejected chunk import included. The fallback is
     "Couldn't load this screen." with one "Reload" button that calls `window.location.reload()`.
     There is no automatic reload, the same choice as D-0162 §3. On `/session/*` a reload is safe,
     because the focus state survives it (D-0111 §6).
   - There is one boundary per route element, not one around `<Routes>`. So leaving by the tab bar
     (where it shows) renders the other route afresh. Within one route the failed `lazy()` stays
     failed until the reload, so no reset on a param change is needed.
   - It has no screen ID of its own and renders inside the route's slot. The tab bar shows or hides
     as it does today.
   - Feature-level boundaries (the UF-09 seam boundary) still catch their own errors first.
8. **T-0446 splits by lane.** T-0446 keeps the seam zone (web-feature:UF-09). **T-0459** is the
   route-chunk boundary (web-shell).

## Consequences

- web-feature:UF-07: T-0454 (with T-0456).

## Revisit when
- Real users report a reload loop or repeated chunk failures after deploys. Then consider one
  automatic reload, guarded by a `sessionStorage` flag.
- iOS stops needing the priming utterance, or a real device speaks it audibly.
- A shared dialog component lands in `components/**` (D-0162's own revisit).
