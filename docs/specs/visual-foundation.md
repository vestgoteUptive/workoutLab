# Visual foundation: fonts, page gutter, heading scale

- **Why:** GitHub #37 (Plan is confusing) and #45 (Account looks horrible). Both screens share three foundation faults that no screen spec can fix alone:
  1. **No design font ships.** No `@font-face` exists anywhere in the repo, so `--wl-font-display` and `--wl-font-body` always resolve to their system fallbacks. Every heading on prod renders in the iOS system font.
  2. **No page gutter on UF-11.** The UF-11 screens (`/plan`, `/plan/edit`, `/plan/account`) have no horizontal padding, so text touches the screen edge. Other screens each set their own `padding: 16px` on their root class. There is no shared rule.
  3. **No heading scale.** `apps/web/src/main.css` styles only `body`. A bare `<h1>`/`<h2>` gets the browser default (system font, 2em/1.5em, bold), which is what UF-11 shows.
- **Decisions:** D-0019 (tokens, self-hosting intent), D-0031 (fallback stacks; its "revisit when the web fonts get self-hosted" trigger fires here), D-0046 §6 (landing fallback until woff2 ships), D-0190 (web CSP), D-0017 (NFRs: offline, a11y).
- **Design source:** `Design-docs/docs/design/design-system.md` and the 390 × 844 prototypes (`prototype/UF02-1-Today.dc.html`, `UF06-1-Progress.dc.html`): page padding 20 px, `h1` Big Shoulders Display 800 40 px uppercase with line height 1, cards `surface` + 1 px `line` + radius 16 px, card labels DM Sans 700 11–12 px uppercase.
- **Screens using this first:** UF-11.2 (`Design-docs/docs/design/screens/UF-11.2.md`) and UF-11.4 (`screens/UF-11.4.md`). Every non-focus screen inherits the fonts and heading scale.

## 1. Self-hosted fonts

### What ships

| Family (must equal the first name in the `tokens.json` stack) | File | Axis / weights | Style | Use |
|---|---|---|---|---|
| `Big Shoulders Display` | `big-shoulders-display-latin-wght.woff2` | variable `wght` 100–900 (we use 700, 800) | normal | titles, numbers, timers |
| `DM Sans` | `dm-sans-latin-wght.woff2` | variable `wght` 100–1000 (we use 400, 500, 700) | normal | everything else |

- **Two files, both variable.** One request per family covers every weight in `tokens.json` (`display.weights` [700, 800], `body.weights` [400, 500, 700]). Five static files would cost more requests for about the same bytes.
- **Upright only.** No italic file. The design uses no italics.
- **Subset: `latin`**, the standard Google Fonts / Fontsource latin range:
  `U+0000-00FF, U+0131, U+0152-0153, U+02BB-02BC, U+02C6, U+02DA, U+02DC, U+0304, U+0308, U+0329, U+2000-206F, U+20AC, U+2122, U+2191, U+2193, U+2212, U+2215, U+FEFF, U+FFFD`.
  This covers Swedish and other Western European names (å ä ö é ü), `·`, `–`, `…`, `×`, `€`.
  - Characters the UI uses outside this range fall back glyph by glyph to the next font in the stack. Today these are `→` (U+2192, check-in rows and previews) and `⅓ ⅔` (U+2153–2154, C-01 legend). This is acceptable: the fallback renders them, with no missing-glyph box.
  - `latin-ext` is **not** shipped in v1. Revisit if a user-visible string needs it (names come from the user's email only, and the email is shown in the body font, which falls back per glyph).
- **Source:** the OFL builds published by Fontsource (`@fontsource-variable/big-shoulders-display` and `@fontsource-variable/dm-sans`, the `latin-wght-normal` woff2 files). Download once, at a pinned version, and **commit the two files** to `packages/design-tokens/fonts/`. There is no runtime npm dependency and no lockfile change. `packages/design-tokens/fonts/SOURCES.md` records the package, the version, the upstream file name and the sha256 of each file.
- **Size budget:** each file ≤ 60 KB, and both together ≤ 110 KB.

### Licence

- Both families are under the **SIL Open Font License 1.1**: Big Shoulders Display (© The Big Shoulders Project Authors, Patric King) and DM Sans (© The DM Sans Project Authors, Colophon/Google).
- The OFL allows bundling and embedding the fonts in an app and a website, including subsetted builds. The one condition that matters here is that the licence text travels with the files. Ship `packages/design-tokens/fonts/OFL-BigShouldersDisplay.txt` and `OFL-DMSans.txt`, each with its upstream copyright line.
- **Reserved Font Name:** the upstream OFL headers for both families declare none, so a subsetted file may keep its family name. The build ticket checks the header text of each `OFL-*.txt` and records the result in `SOURCES.md`. If either header declares an RFN, stop and raise triage. Don't rename the font silently.
- The fonts are never sold on their own. No attribution is needed in the UI.

### `@font-face` (design-tokens lane)

- `packages/design-tokens` gains `fonts.css`, exported as `@workoutlab/design-tokens/fonts.css`. It is either generated by `scripts/build-css.mjs` from `tokens.json`'s family names or kept static and checked by a test. The family names come from `tokens.json`; they are never retyped.
  ```css
  @font-face {
    font-family: "DM Sans";
    src: url("../fonts/dm-sans-latin-wght.woff2") format("woff2");
    font-weight: 100 1000;
    font-style: normal;
    font-display: swap;
    unicode-range: U+0000-00FF, U+0131, …; /* the latin range above */
  }
  /* the same for "Big Shoulders Display", font-weight: 100 900 */
  ```
- **`font-display: swap`** for both faces. Text is never invisible, and with preload plus precache the swap happens before the first paint on every load except the very first, cold one. `optional` was rejected: on a slow first visit it can keep the system font for the whole session, which is the bug we are fixing.
- No `local()` source, so a different local install can't override the shipped build.
- No `data:` URIs. The web CSP has no `font-src data:` and must not gain one.
- `tokens.json` is **unchanged**: the stacks (D-0031) and weights are already correct. Fonts need no contract change.

### Loading in the apps

- **Web (web-shell lane):**
  - `apps/web/src/main.tsx` imports `@workoutlab/design-tokens/fonts.css` before `tokens.css`. Vite rewrites the `url()`s and emits hashed files under `/assets/`.
  - **Preload both files.** The build plugin in `vite.config.ts` (the same place that injects the CSP meta) adds `<link rel="preload" href="/assets/<hashed>.woff2" as="font" type="font/woff2" crossorigin>` for each file to `dist/index.html`. `crossorigin` is required even for same-origin fonts, or the preload is fetched twice.
  - **Offline:** add `woff2` to `workbox.globPatterns` (today `**/*.{js,css,html,webmanifest,png}`), so the fonts are precached and render offline (D-0017 NFR-OFF).
  - Optional: in `_headers`, `/assets/*` gets `Cache-Control: public, max-age=31536000, immutable`. The files are hash-named.
- **Landing (landing lane):** `apps/landing` imports the same `fonts.css` in its layout, with the same preload links. Re-run T-0309 AC23 (CLS ≤ 0.1 with the font swap).

### CSP impact

- **Web app: none.** `default-src 'self'` already covers fonts, and there is no `font-src` directive to widen. Self-hosting is what keeps it that way: a font CDN would need `font-src https://fonts.gstatic.com` and `style-src https://fonts.googleapis.com`. Keep `security-headers.mjs` unchanged.
- **Landing: one directive.** Its policy is `default-src 'none'; style-src 'self'; …`, which **blocks every font**. Add `font-src 'self'` to `apps/landing/public/_headers` and to the pinned string in `apps/landing/test/t0511-headers.test.ts`. This is a security-header change, so the security reviewer signs off on that ticket.

### Acceptance criteria: fonts

- **F-1 (package, vitest):** `fonts.css` has exactly two `@font-face` blocks. Each `font-family` equals the first family in the matching `tokens.json` stack. Each `font-weight` range covers every weight in that role's `weights`. Each has `font-display: swap`, a `unicode-range`, and one `src` that is a relative `url(...woff2)` with `format("woff2")`. No `http`, no `data:`, no `local(`.
- **F-2 (package, vitest):** both woff2 files exist, start with the `wOF2` signature, and are within the size budget. `OFL-BigShouldersDisplay.txt` and `OFL-DMSans.txt` exist and contain "SIL OPEN FONT LICENSE Version 1.1". The sha256 of each file matches `SOURCES.md`.
- **F-3 (web build test, `apps/web/build.test.ts`):** `dist/` contains two `.woff2` assets. `dist/index.html` has two `<link rel="preload" as="font" type="font/woff2" crossorigin>` tags whose `href`s exist in `dist/`. The generated service worker's precache manifest lists both. The CSP string is unchanged, and no file in `dist/` contains `fonts.googleapis` or `fonts.gstatic`.
- **F-4 (Playwright, web):** on `/welcome` and `/plan`, after `document.fonts.ready`:
  - `document.fonts.check('800 40px "Big Shoulders Display"')` and `document.fonts.check('400 16px "DM Sans"')` both return true;
  - the `FontFace` entries for both families have `status === "loaded"`;
  - every font response comes from the app's own origin with status 200.
- **F-5 (Playwright, web, offline):** after the service worker is active, set the context offline, reload `/plan`, and F-4's two `fonts.check` calls still return true.
- **F-6 (landing, vitest + browser):** the landing `_headers` CSP contains `font-src 'self'`, and the built CSS has the two `@font-face` rules with same-origin `src`. T-0309 AC23 (CLS ≤ 0.1) passes with the fonts on.

## 2. Page gutter and max width

### Rule

- **One class, `.wl-page`,** in `apps/web/src/main.css` (web-shell). Every non-focus screen root uses it. Screens adopt it one by one, and UF-11 adopts it first.
  ```css
  .wl-page {
    box-sizing: border-box;
    inline-size: 100%;
    max-inline-size: 640px;           /* page max width */
    margin-inline: auto;              /* centred on tablets and desktop */
    padding-inline: max(20px, env(safe-area-inset-left)) max(20px, env(safe-area-inset-right));
    padding-block: max(24px, env(safe-area-inset-top)) 32px;
    display: flex;
    flex-direction: column;
    gap: 16px;                        /* between cards / sections */
  }
  ```
- **Gutter: 20 px**, from the prototypes and design-system.md ("Page padding 20–24 px"). The orchestrator's note said 16 px. 16 px is the floor the tests enforce on every screen; 20 px is the target value for `.wl-page`. The landscape safe-area inset wins when it is wider.
- **Top:** `index.html` sets `viewport-fit=cover`. In the iOS standalone PWA, content can sit under the status bar unless the top padding respects `safe-area-inset-top`.
- **Max width: 640 px**, centred. This is a phone-first app, so 640 keeps line length readable (about 70 characters at 16 px) and the 3-column target grid compact on tablets and desktop.
- **Exempt:** UF-09 focus mode (`.wl-uf09`, a full-bleed `bg-focus` layout with its own padding) and the C-02 tab bar (full width, fixed).
- **Migration:** the screens that already pad 16 px on their root (`.wl-today`, `.wl-preview`, `.wl-uf04`, `.wl-routine-editor`, `.wl-progress`, `.wl-balance`, `.wl-uf03-list`, `.wl-uf08`) keep working. They pass the 16 px floor. They switch to `.wl-page` in a later sweep, one feature ticket each, and drop their own horizontal padding when they do, so the gutter is never doubled.

### Acceptance criteria: gutter

- **G-1 (Playwright, 360 × 740):** on `/`, `/library`, `/progress`, `/balance`, `/plan`, `/plan/edit` and `/plan/account`:
  - the left edge of the `<h1>` is ≥ 16 px from the viewport's left edge;
  - every visible text node and control inside the screen root has its right edge ≤ 344 px;
  - `document.documentElement.scrollWidth` ≤ 360 (no horizontal scroll).
- **G-2 (Playwright, 360 × 740):** on the UF-11 screens, which use `.wl-page`, the screen root's computed `padding-left` and `padding-right` are both `20px`.
- **G-3 (Playwright, 1024 × 768):** on `/plan`, the screen root's width is ≤ 640 px and it is centred: the left and right space differ by ≤ 1 px.
- **G-4 (Playwright, 320 × 640, WCAG 1.4.10 reflow):** on `/plan` and `/plan/account`, there is no horizontal scroll and no text is clipped. Each `h1` and email line has `scrollWidth` ≤ `clientWidth`.

## 3. Type scale

Sizes are given in px for reading. **Write text sizes in `rem`** (1 rem = 16 px), so browser text zoom scales them (WCAG 1.4.4). Every role uses token fonts and token colours only.

| Role | Element / class | Font | Size / line height | Weight | Case, tracking | Colour |
|---|---|---|---|---|---|---|
| Page title | `h1` (global) | display | `clamp(2rem, 10vw, 2.5rem)` (32–40 px) / 1.0 | 800 | uppercase, 0.01em | `text` |
| Section title | `h2` (global) | display | 1.5rem (24 px) / 1.1 | 800 | uppercase, 0.01em | `text` |
| Card label | `.wl-label` (an `h2`/`h3` inside a card, or a `legend`) | body | 0.75rem (12 px) / 1.33 | 700 | uppercase, 0.08em | `text-muted` |
| Stat number | `.wl-stat` | display | 1.75rem (28 px) / 1.0; 2.125rem (34 px) for a hero stat | 800 | tabular | `text` |
| Body | `body` | body | 1rem (16 px) / 1.5 | 400 | none | `text` |
| Body strong | row titles, values | body | 1rem / 1.4 | 500 or 700 | none | `text` |
| Secondary | `.wl-muted` | body | 0.875rem (14 px) / 1.4 | 400 | none | `text-muted` |
| Caption | small meta | body | 0.8125rem (13 px) / 1.3; never under 12 px | 500 | none | `text-muted` |
| Button | primary / secondary | body | 1rem / 1.2 | 700 (primary), 500 (secondary) | none | per button |
| Focus numbers | UF-09 only | display | 104–180 px (unchanged) | 800 | none | `text` |

- Global `h1`, `h2` and `body` rules go in `main.css` (web-shell). Margins reset to 0: spacing comes from the `.wl-page` and card `gap`, never from heading margins.
- Uppercase is CSS `text-transform` only. DOM text keeps its catalogue case, so accessible names and existing `getByRole({ name })` tests don't change.
- Headings always wrap. They are never truncated or ellipsised.

### Shared surfaces (used by UF-11.2 and UF-11.4)

These are existing tokens in a shared class, not new components:

- **Card `.wl-card`:** `surface` fill, 1 px `line` border, radius 16 px, padding 16 px, a flex column with gap 12 px.
- **Row link `.wl-row`:** the whole row is the link, min height 56 px, padding-block 12 px, text left, a 2 px stroke chevron at the right edge (`text-muted`, `aria-hidden`). Rows inside a card are divided by a 1 px `line` rule.
- **Buttons:** primary `accent` fill, `on-accent` text, min height 54 px, radius 14 px, full card width. Secondary: `surface-2` fill, 1 px `line-strong` border, `text`, min height 48 px, radius 14 px. Text button: no fill, `text`, underline, min 44 × 44 px. Every button gets a 2 px `accent` focus ring at a 2 px offset.
- **Text input:** `bg` fill, 1 px **`text-muted`** border (6.8:1 on `surface`, which meets 3:1 for a UI component boundary, WCAG 1.4.11; `line-strong` is only 1.5:1), radius 12 px, min height 48 px.

### Acceptance criteria: type

- **T-1 (Playwright, 390 × 844):** on `/plan` and `/plan/account`:
  - `getComputedStyle(h1).fontFamily` starts with `"Big Shoulders Display"`, its `fontWeight` is `800`, its `textTransform` is `uppercase`, and its `fontSize` is between 32 and 40 px;
  - `getComputedStyle(document.body).fontFamily` starts with `"DM Sans"`.
- **T-2 (Playwright, 390 × 844):** on `/plan`, each card label's computed `fontSize` is 12 px, `textTransform` is `uppercase` and `color` equals the `text-muted` token. Body text is 16 px.
- **T-3 (Playwright):** with the root font size at 200 % (`html { font-size: 32px }` injected), the `/plan` `h1` and body text double in size, and G-1's no-horizontal-scroll check still holds at 390 px width.
- **T-4 (vitest, `main.css` as text):** `main.css` sets `font-family: var(--wl-font-display)` on `h1, h2` and `var(--wl-font-body)` on `body`. It has no raw colour (existing guard) and no `px` font sizes (rem only).

## 4. Tokens: spacing and type sizes (decision needed)

The design role brief says `tokens.json` is the single source for type, spacing and radius as well as colour. Today it holds colour and font families only. The values above can either:

- **(a) become tokens.** This is the recommended option. A new decision adds `space` (`gutter` 20, `page-max` 640, `stack` 16, `card-pad` 16), `radius` (`card` 16, `button` 14, `input` 12) and `size` (the type scale above) groups to `tokens.json`, with `build-css.mjs` emitting `--wl-space-*`, `--wl-radius-*` and `--wl-size-*`. The landing and web then share one scale. Since `tokens.json` is a contract, this follows the full-gate `--force` rule, so it runs in the design ticket. Or:
- **(b) stay CSS** in `apps/web/src/main.css`. This is faster and makes no contract change, but the landing keeps its own copy.

Either way, the screen specs refer to the roles by name (gutter, card, label), not to raw numbers, so they don't change.
