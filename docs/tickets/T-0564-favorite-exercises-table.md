### Edge cases that are in scope
- **Double tap / second device:** a duplicate insert with `on conflict do nothing` is not an error (AC4).
- **Concurrent favorite and exclude from two devices:** both rows may exist; no DB error; the engine's precedence makes it safe (documented, AC5 proves each single direction).
- **A library row is removed:** the favorite cascades away (AC6).
- **Account deletion:** rows go with the auth user (AC7).
- **Zero favorites:** the export has `favorite_exercises: []` (AC8).
- Offline, time running out, returning after 10 days: no DB behaviour (device side, T-0567).

## Acceptance criteria
Run pgTAP on a fresh local `supabase db reset` (Docker); record counts in `testsRun`.
- **AC1 (schema)** `001_schema` asserts the table, its three columns (types, nullability, defaults), the PK, the index and both `on delete cascade` FKs; the column block matches `docs/data-model.md`.
- **AC2 (server-set created_at)** Given A inserts (A, back-squat) with `created_at` '2020-01-01', Then the stored value is the transaction's `now()`. When A updates `created_at` to '2020-01-01' or `user_id` to B, Then both keep their old values.
- **AC3 (isolation)** Given A favorited back-squat, When B selects, inserts (with `user_id` A), updates or deletes A's rows, Then B sees 0 rows, the insert fails with an RLS error and update/delete change 0 rows. Given `anon`, Then select and insert fail with a privilege error.
- **AC4 (idempotence)** When A inserts (A, back-squat) again with `on conflict (user_id, exercise_id) do nothing`, Then one row and no error. When A deletes (A, lateral-raise), which doesn't exist, Then 0 rows and no error.
- **AC5 (mutual exclusion, both directions)** Given A excluded back-squat and B excluded back-squat, When A favorites back-squat, Then A has a favorite row and no exclusion row, and B's exclusion row is untouched. Given A favorited bench-press and B favorited bench-press, When A excludes bench-press, Then A has an exclusion row and no favorite row, and B's favorite is untouched.
- **AC6 (exercise cascade)** Given A favorited back-squat, When the back-squat library row is deleted as `postgres` (rolled-back transaction, no referencing `session_sets`/`routine_items`), Then A's favorite is gone.
- **AC7 (auth cascade)** Given A has two favorites, When A's `auth.users` row is deleted, Then A has 0 rows (`007_account_deletion` and `account-delete.test.ts`).
- **AC8 (export)** Given A favorited lateral-raise then bench-press, When A exports (UF-11.4), Then `tables.favorite_exercises` lists bench-press before lateral-raise, the file has 9 table keys and `version` 1. Given no favorites, Then `tables.favorite_exercises` is `[]`.
