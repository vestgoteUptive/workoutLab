## Why
NFR-PRIV-5 needs a server-side delete of the caller's `auth.users` row. D-0135 makes it a fourth Edge Function. The contract comes first, so the backend (T-0310b) and the web (T-0310c/d) code against the same `DELETE /account`.

## Scope
- In:
  - `api/openapi.yaml`, exactly as D-0135 §1 says:
    - the new `account` tag;
    - the `/account` → `delete` operation (`operationId: deleteAccount`, `tags: [account]`, the summary text verbatim, a description, responses `"204"` with no `content`, `"401"` → `Unauthorized`, `"500"` → `Internal`);
    - `info.description` saying "four" functions.
  - Regenerate `packages/shared/src/api.gen.ts` with `pnpm --filter @workoutlab/shared gen:api`. `session-plan.validate.gen.ts` must come out byte-identical, because no schema changes.
  - `packages/shared/test/openapi.test.ts`:
    - AC2 lists the four operations;
    - the AC5 expected-responses map adds `"DELETE /account": ["401", "500"]`.

    These are the only edits to existing tests.
  - A new test file `packages/shared/test/t0310a-delete-account.test.ts` for the ACs below.
  - Edge cases: a repeat delete (the description says 401, never 404), no request body, no new error code.
- Out:
  - The function itself (T-0310b), `supabase/**`, the vendor copy (regenerated by the orchestrator at merge, D-0053 §1), any web code, `docs/data-model.md` (unchanged) and every component schema.

## Acceptance criteria
Each new test title starts with `T-0310a ACn`.

- **AC1 (the operation, red on `main`)**
  - **Given** `api/openapi.yaml`, **When** the test reads `spec.paths["/account"]`, **Then** it has exactly one method, `delete`, with:
    - `operationId` `"deleteAccount"`;
    - `tags` `["account"]`;
    - a `summary` containing `UF-11.4` and `NFR-PRIV-5`;
    - no `requestBody`;
    - no `parameters`;
    - no operation-level `security` (the global `bearerAuth` applies).
  - The top-level `tags` array contains an entry with `name: "account"`.
  - **Red on unfixed code:** on `main`, `spec.paths["/account"]` is undefined. Record the red run in the build log.
- **AC2 (responses)**
  - The response keys are exactly `["204", "401", "500"]`.
  - `"204"` has a `description` and **no** `content` key.
  - `"401"` is `{ $ref: "#/components/responses/Unauthorized" }` and `"500"` is `{ $ref: "#/components/responses/Internal" }`.
  - **Contrast:** there is no `"404"`, `"403"` or `"400"`.
- **AC3 (description)**
  - The operation's `description` contains `on delete cascade` and `D-0020`.
  - It contains `A repeat call with the same token is 401` and `never 404` (D-0135 §1).
  - `info.description` contains `four server-side functions`, and doesn't contain `three server-side functions`.
- **AC4 (the existing contract tests)**
  - `openapi.test.ts` AC2 now expects exactly `["DELETE /account", "GET /balance", "POST /sessions/{id}/finish", "POST /workouts/suggest"]` (sorted).
  - The AC1 redocly lint has 0 errors.
  - The AC3 "every UF-NN(.n) exists in the v2 flow index" test passes. UF-11.4 is in the flow index as of D-0136 §1.
  - The AC4 "each operation has the shared 401" test passes unedited.
  - AC11 (device-only components) passes unedited.
- **AC5 (generated types)**
  - `packages/shared/src/api.gen.ts` contains a `"/account"` path entry with a `delete` operation, and an `operations["deleteAccount"]` entry.
  - `types.test.ts` "api.gen.ts is byte-identical to a fresh openapi-typescript run" passes.
  - `session-plan.validate.gen.ts` has no diff (`git diff main...HEAD -- packages/shared/src/session-plan.validate.gen.ts` is empty).
- **AC6 (no other contract moves)**
  - `git diff main...HEAD -- api/openapi.yaml` touches only `info.description`, `tags` and the new `/account` path. List the hunks in the build log.
  - `docs/data-model.md` and `supabase/**` have no diff.
