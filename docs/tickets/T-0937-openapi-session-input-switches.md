## Why
T-0936 adds two optional switches to the engine's `SessionInput` (D-0237). The `/workouts/suggest` Edge Function shares that type through `api/openapi.yaml` (D-0001). D-0237 §3 names this contract change. D-0239 makes it **deferrable**: the app runs `suggest` on the device (D-0063 §3) and never calls `/workouts/suggest` with the new keys, and no web, engine or QA ticket depends on this one. Until it lands, the endpoint returns 400 for the two keys.

## Scope
- In: `api/openapi.yaml` `components.schemas.SessionInput` gains `autoMainLift` (boolean, optional, description "Rule 7.2 step 1. Absent or true: pick a main lift when `mainLiftId` is null. false: no fallback main lift (D-0237).") and `fill` (boolean, optional, "Rule 7.2 step 3. Absent or true: fill the remaining time. false: only the main lift and pins (D-0237)."). Neither joins `required`; `additionalProperties: false` stays. One request example for empty mode (`autoMainLift: false`, `fill: false`, `pinnedIds: ["leg-extension"]`). Regenerate `packages/shared/src/api.gen.ts` with `pnpm --filter @workoutlab/shared gen:api` and add a test. Re-vendor with `node supabase/scripts/vendor.mjs`, since `packages/shared/src` is vendored.
- Out: the validator (T-0938); the engine (T-0936); `Workout` (unchanged, the switches are never echoed, D-0239 §4).

## Acceptance criteria
- AC1 Given the regenerated `api.gen.ts`, Then `components["schemas"]["SessionInput"]` has `autoMainLift?: boolean` and `fill?: boolean`, both optional (a type-level test in `packages/shared/test/` with `expectTypeOf`, plus a `@ts-expect-error` for a string value).
- AC2 Given `api/openapi.yaml`, When it is linted by the existing openapi test (`packages/shared/test/openapi.test.ts`), Then it is valid, `SessionInput.required` is unchanged, and the empty-mode example validates against `SessionInput`.
- AC3 Given a `SessionInput` example without the two keys (every existing example), Then it still validates (absent = true is the default; the binary sibling of AC2's example).
- AC4 Given the `SessionInput` example with `autoMainLift` or `fill` set to `"false"`, `0` or `null`, Then `isValid("SessionInput", …)` is false, and `SessionInput` exported from `packages/shared/src/index.ts` types both keys as `boolean | undefined` (the `t0565-favorite-ids.test.ts` pattern, new file `t0937-session-switches.test.ts`).
- AC5 Given the change, When `node supabase/scripts/vendor.mjs --check` runs, Then it exits 0.
