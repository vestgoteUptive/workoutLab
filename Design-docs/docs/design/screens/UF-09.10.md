# UF-09.10 Add exercise

- **Screen:** UF-09.10 Add exercise, a sheet over focus mode, opened only from the "Add exercise" action on UF-09.9 Paused (`UF-09.9.md`). No URL change. Nothing on UF-09.1 to UF-09.8 opens it (principle 1). The workout stays paused the whole time the sheet is open, with every timer stopped.
- **Decisions:** D-0243 (entry, list, row states, copy), D-0246 (§2 widened "In this workout", §3 accessible names, §6 Back and Escape, §7 focus and status, §16 self-contained sheet, §18 this file), D-0244 (`timeLeftS`, the lead line), D-0205 §2 (search and list rules), D-0202 (Favorites), D-0199 (Excluded), D-0231 (no level pointer in UF-09), D-0211 (plan sheet), D-0208, D-0203. Spec: `docs/specs/add-exercise-in-session.md`.
- **Modelled on:** `UF-08.5.md` (search, Favorites, "Today's areas", result row). Where this file is silent, UF-08.5 applies. Where the two differ, the table "How this sheet differs from UF-08.5" below wins.
- **Look:** Cobalt + state colour (D-0208); state `plan`; patterns in `components/state-patterns.md`. The D-0211 plan sheet (the Sheet pattern, as the UF-05.1 swap sheet): plan-coloured even over a lift or rest screen, dimmed behind by `--wl-scrim`.
- **Root (D-0246 §16):** the sheet's root element carries `class="wl-uf08"` and `data-wl-state="plan"`, so it matches `.wl-uf08[data-wl-state="plan"]` and the UF-08 row and button rules (44 px targets) apply even when SessionSetup was never loaded (after a reload into UF-09). The module that renders it imports the UF-08 stylesheet itself.
- **Type:** Familjen Grotesk through `--wl-font` (the plan font, `--wl-font-plan`), in the plan roles of `design-system.md`. Never the session font, even over a lift or rest screen. Sentence case; no uppercase transforms.
- **Foundation classes (D-0203):** `.wl-row` (hairline rows: 12 px vertical padding, a 1 px `--wl-line` bottom hairline, no fill, no border box) and `.wl-label` (section headings). Shared patterns: the Sheet, the Input, the Secondary button and the neutral notice. The same sheet classes UF-08.5 uses (`wl-sheet`, `wl-uf08__sheet`, `wl-uf08__pick`, `wl-uf08__pick-add`, `wl-uf08__sheet-status`). No boxed rows.
- **Tokens:** existing only (`--wl-bg`, `--wl-raise`, `--wl-line`, `--wl-ink`, `--wl-ink-muted`, `--wl-focus`, `--wl-scrim`, `--wl-font`). No new token, no hex (D-0246 §18).

## Layout (full-height sheet, 320 px and 390 px wide, top to bottom)

1. Grabber (40 × 4, `--wl-line`, `aria-hidden`). Header: title "Add exercise" (`h2`, section title role, sentence case) and **Close** (44 × 44 px target, top right, ✕ glyph `aria-hidden`, accessible name "Close").
2. Lead line, `--wl-ink-muted`: "{m} min left", or "No time left" (see Lead line).
3. Search field, visible label "Search exercises", `type="search"`, 48 px tall, 1 px `--wl-ink-muted` boundary, a 44 px clear button when it has text. **Focused on open.**
4. Status line, `role="status"`, present on mount, empty until a refusal. When it has text it is the neutral notice (`--wl-raise` fill, `--wl-ink` text), directly under the search field. A failed write uses a separate `role="alert"` line in the same place.
5. The list: sections with an empty query, results with a query.

At 320 px nothing scrolls sideways; names, area lines and reason lines wrap, never truncate. The sheet body scrolls; the header, lead line, search field and status line stay visible.

## Lead line (D-0243 §2, D-0244 §2)

- **Copy:** "{m} min left", where `m = floor(timeLeftS / 60)`. When `timeLeftS < 60` (zero or negative included) it reads "No time left".
- `timeLeftS` is the engine's value for the live paused state, read once when the sheet opens and again after every refusal. The lead line is plain text, not a live region (the status line carries announcements).

| `timeLeftS` | Lead line |
|---|---|
| 945 s | "15 min left" |
| 165 s | "2 min left" |
| 60 s | "1 min left" |
| 45 s | "No time left" |
| −200 s | "No time left" |

The engine's model limits apply as written in the spec (paused in a rest it can read up to 120 s high; paused mid-set it reads low). The sheet shows the engine's number and never corrects it.

## Empty query (D-0205 §2, D-0202)

1. **Favorites** (`h2`, `.wl-label`): stored favorites, by name then id, in one hairline list. **Omitted when the user has no favorites** (nothing rendered, no empty heading).
2. **Today's areas** (`h2`, `.wl-label`): one `<section aria-labelledby>` per primary area of the plan's items, **in the fixed area order** (chest, back, shoulders, arms, core, glutes, quads, hamstrings, calves), each headed by the area as an `h2` in `.wl-label`. **Skipped and done items count**: their areas are listed like any other item's. Inside: exercises with weight 1.0 in that area, by name then id, as hairline rows. An exercise already shown under Favorites is not repeated.
3. Warm-up moves never appear.
4. There is **no "Suggested" section** in v1 (D-0243 §2, D-0246 §1, open question 4).

With no favorites the sheet shows "Today's areas" only. A plan in focus mode always has at least one item, so "Today's areas" is never empty.

## Query (D-0205 §2)

The UF-08.5 field and rule: a case-insensitive substring match on the name over the cached library (kind `exercise`), sorted by name then id, as one flat hairline list with no section headings. No match: "No exercises match “{query}”." (`--wl-ink-muted`, centred).

## Result row

- A `.wl-row` hairline row inside a `<ul>`: min 64 px, wraps. Line 1: the name (row title role, 1.0625 rem, 600, `--wl-ink`) and, for a favorite, the "Favorite" tag after it (the UF-08.2 pill). Line 2: primary areas ("Back, Quads", `--wl-ink-muted`, 13 px). Line 3, only on a disabled row: the reason line (`--wl-ink-muted`, 13 px).
- **Addable row:** one button, **"Add"** (Secondary button, at least 44 px tall and 96 px wide, below the text). Its accessible name is **"Add {name}"**, or **"Add {name}, {area}"** when the exercise shows under more than one "Today's areas" section (D-0246 §3). The visible text "Add" starts the name (WCAG 2.5.3). Names are unique on the sheet.
- There is **no "Start with this"**: an added item is never the main lift (D-0243 §2).
- Add is a secondary button on purpose: the sheet has no primary action.

## Row states (D-0243 §3, D-0246 §2)

**First match wins.** A disabled row shows its reason line and **cannot add**: the text is the only signal (no colour, no icon). As on UF-08.5, the row's Add button keeps its place and size, stays focusable and is dimmed (`--wl-ink-muted` outline and text, 5.9:1), with `aria-disabled="true"` and `aria-describedby` pointing at the row's reason line; tapping it does nothing and writes nothing. The spec's "no Add" means no working Add: keeping the inert button lets a keyboard or screen-reader user land on the row and hear why. The `disabled` attribute is never used.

| Order | Reason line | When |
|---|---|---|
| 1 | "Skipped in this workout" | The exercise is a skipped plan item |
| 2 | "In this workout" | Any other plan item (done, current or still to come), **or** an exercise with a set logged in this workout that is no longer a plan item (swapped out after sets were logged, D-0246 §2) |
| 3 | "Excluded" | On the stored excluded list (D-0199) |
| 4 | "Not available with your equipment" | Needs equipment the profile doesn't have |
| 5 | "Above your level" | Above the profile level. No Plan pointer, no link, nothing points out of focus mode (D-0231) |
| 6 | "{Area} is recovering" | A primary area recovering **at the session's start**: `recoveringAreas` over the history before `started_at`, at `now = started_at`. Sets logged in this workout never block the area being trained |

There is no "Skipping {Area} today" row: the session row doesn't store UF-08.1's Skip today, and the add is the user's explicit choice (D-0243 §3).

## Add and refusals (D-0243 §5 §6, D-0246 §4)

- **Add** asks the focus machine to insert the exercise right after the current exercise. One tap, no confirm.
- **Success:** the sheet closes and the screen stays on UF-09.9 Paused. Paused's own status line says "{name} added after {current name}." and focus lands on "Add exercise" (`UF-09.9.md`, item 7). The sheet announces nothing itself.
- **Refused:** the sheet stays open, nothing is written and the plan is unchanged. The sheet's `role="status"` line says exactly one of:

| Refusal | Status line |
|---|---|
| `time`, m ≥ 1 | "{name} doesn't fit in the {m} min left." |
| `time`, m = 0 | "{name} doesn't fit. No time left." |
| `items_cap` (8 items, done and skipped included) | "This workout has 8 exercises, the most it can hold." |

- **Write failed:** "Couldn't add {name}. Try again." in a `role="alert"` line (`--wl-raise` strip, `--wl-ink`), in the status line's place. The sheet stays open, the plan and the logged sets are unchanged, and the Add can be tapped again.
- `{m}` in a refusal is the same `floor(timeLeftS / 60)` as the lead line. The text clears on the next Add or when the sheet closes. It is not the attention colour. Focus stays on the Add button that was tapped.
- **Worked values:** 165 s left, Lateral raise → "Lateral raise doesn't fit in the 2 min left."; 45 s left → "Lateral raise doesn't fit. No time left."

## Close, Escape and Back (D-0246 §6)

- **Close**, **Escape** and browser **Back** (`popstate`) close **only the sheet**. Nothing navigates, nothing ends, nothing is written.
- Focus returns to "Add exercise" on UF-09.9.
- The workout **stays paused**: the machine was already paused, so the Back→Pause guard has nothing to do.
- Tapping the scrim does nothing (as UF-05.1); the sheet closes only through the three ways above.

## States and focus

| State | What shows |
|---|---|
| Online / offline | Identical. The library, favorites, excluded list, profile and history come from the device cache; the engine runs on the device; the plan write is queued. No offline line |
| Empty query, with favorites | "Favorites", then "Today's areas" |
| Empty query, no favorites | "Today's areas" only |
| Query with matches / without | Flat list / "No exercises match “{query}”." |
| `timeLeftS` ≥ 60 / < 60 | "{m} min left" / "No time left"; every Add is still tappable and refused with the time line when it doesn't fit |
| 8 items | Rows look as usual; any Add is refused with the cap line |
| Refused | Sheet open, refusal in the status line, focus on the tapped Add |
| Write failed | Sheet open, `role="alert"` line, focus on the tapped Add |
| Success | Sheet closes; UF-09.9 status line; focus on "Add exercise" |
| Closed (Close, Escape, Back) | Sheet closes; focus on "Add exercise"; still paused |

The sheet traps focus while open. Focus ring 2 px `--wl-focus`, offset 2 px (inset on full-width rows so it isn't clipped).

## How this sheet differs from UF-08.5 (D-0246 §18)

| | UF-08.5 Add exercise (planning) | UF-09.10 Add exercise (in a workout) |
|---|---|---|
| 1. Plan-item rows | "In this workout" for any item | "Skipped in this workout" for a skipped item; "In this workout" for any other item **and** for an exercise with a set logged this workout that is no longer an item |
| 2. Excluded / level rows | "Excluded. Include it again in Plan › Excluded exercises." and "Above your level. Change it in Plan › Edit plan." | Short lines "Excluded" and "Above your level", no Plan pointer (D-0231) |
| 3. Skip today | "Skipping {Area} today" row | No such row |
| 4. Recovery | Measured now | Measured at `started_at`, over the history before it |
| 5. Start with this | On compound rows | None |
| 6. Lead line | "The rest of your workout adjusts to fit {n} min." (or the empty-mode "{left} of {n} min left.") | "{m} min left", or "No time left" |

Everything else (search field, sorting, Favorites first, "Today's areas" in the fixed order, the no-match line, the "Add {name}, {area}" names, row anatomy, the Sheet pattern) is the same as UF-08.5.

## Accessibility

- Dialog `role="dialog"`, `aria-modal="true"`, labelled by the "Add exercise" title. The search field has a visible label, not a placeholder only.
- Every target at least 44 × 44 px (WCAG 2.5.8): Close, the clear button, each Add (44 px tall, 96 px wide), the search field (48 px). This holds when the sheet renders with no SessionSetup in the tree, because the root carries `.wl-uf08[data-wl-state="plan"]`.
- Names unique: "Add {name}" / "Add {name}, {area}"; the visible text starts the name.
- A disabled row's Add is `aria-disabled="true"` (never `disabled`), still focusable, with the row's reason in `aria-describedby`; it does nothing when tapped.
- One `role="status"` line on the sheet, present and empty on mount (the sheet is modal, so it is the only live surface while open). A failed write uses `role="alert"`.
- Contrast (D-0211 §4): `--wl-ink` on `plan.bg` 8.6:1; `--wl-ink-muted` on `plan.bg` 5.9:1 (lead line, area and reason lines); `--wl-ink` on `--wl-raise` 6.2:1 (status and alert lines; never `--wl-ink-muted` on `--wl-raise`). The search boundary `--wl-ink-muted` 5.9:1 (needs 3:1). Hairlines `--wl-line` are decorative and never the only cue.
- No motion beyond the sheet's appearance; instant under `prefers-reduced-motion`.
- Passes axe with the sheet open.
- Build: web-feature:UF-08 (T-0948) for the sheet, web-feature:UF-09 (T-0949) for the entry, the status line and focus.

## Checklist (D-0197 §7)

- With favorites / without favorites: Empty query, and States.
- Time left at or above 60 s / below 60 s: Lead line, and Add and refusals.
- Pause from UF-09.8 / any other pause: the sheet is never reachable from a UF-09.8 pause, because "Add exercise" is hidden there (`UF-09.9.md`).
