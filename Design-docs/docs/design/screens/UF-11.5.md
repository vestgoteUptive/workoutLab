# UF-11.5 Excluded exercises

- **Screen:** UF-11.5 Excluded exercises, route `/plan/excluded`. Reached only from the UF-11.2 row (see `UF-11.2.md`). Never reachable from UF-03, UF-08 or UF-09.
- **Decisions:** D-0199 (§8 notice, §9 empty states, §10 design), D-0003, D-0019. Spec: `docs/specs/excluded-exercises.md`.
- **Components:** C-03 is not used here. Neutral notice (`../components/neutral-notice.md`). Tokens only: `bg`, `surface`, `line`, `line-strong`, `text`, `text-muted`, `accent`, `on-accent`, `surface-2`.

## Layout (390 px frame, top to bottom)

1. Back link to UF-11.2 (44 px target).
2. Title "Excluded exercises" (Big Shoulders Display, uppercase) and the lead line in `text-muted`: "These are never suggested or offered as a swap. Your past sets still count."
3. The neutral notice, only when the engine's `excludedOutAreas` is not empty (see "Notice").
4. The offline line, only offline: "Connect to change excluded exercises" (`text-muted`, 13 px). Its element id is the one `aria-describedby` target on this screen.
5. Search field, label "Search exercises" (visible label, not placeholder only). `line-strong` 1 px border, `surface` fill, 48 px tall, a clear button (44 px) when it has text. `type="search"`, no autofocus.
6. A status line (`role="status"`, present on mount, empty at first) for announcements such as "Bench press excluded" and "Bench press included again".
7. Result list, one `surface` card per row, 8 px gap.

## Rows

Each row is at least 64 px tall and wraps rather than truncates. Left: name (DM Sans 700, 16 px, `text`, wraps) and below it the primary areas ("Chest, Shoulders", `text-muted`, 13 px). On the empty query, a third line "Excluded {d MMM}" (for example "Excluded 3 Oct", `text-muted`, 13 px). Right: one button, at least 44 px tall and 96 px wide.

| Context | Row text | Button |
|---|---|---|
| Empty query | name, areas, "Excluded {d MMM}" | **Include again**, secondary (`line-strong` border, `text`) |
| Query, excluded exercise | name, areas, "Excluded" (text, not colour) | **Include again**, secondary |
| Query, other exercise | name, areas | **Exclude**, secondary |

- Accessible names are unique: "Exclude {name}" and "Include {name} again". The visible text is the short form; the name is set with `aria-label`, which begins with the visible text (WCAG 2.5.3).
- Empty query: the excluded list sorted by name, then id. With a query: case-insensitive substring matches over library rows of kind `exercise`, sorted by name, then id. Warm-up moves never appear.
- No row is ever removed from view by the app's own timer.

## States

| State | What shows |
|---|---|
| Loading | The list area shows three skeleton rows (`surface-2`); the cache is shown at once when it exists, so a skeleton appears only on first load |
| Non-empty | The rows above |
| Empty, no query | "No excluded exercises. Search to exclude one, or tap Remove on a suggested workout." (`text-muted`, centred in the list area) |
| Empty, with query | "No exercises match “{query}”." |
| Offline | The list still reads from this user's cache and the notice still shows. Every Exclude / Include again button gets `aria-disabled="true"` and `aria-describedby` pointing at the one offline line. Search still works. Buttons are dimmed (`text-muted` text), same size, still focusable. The controls are enabled again without a reload when the connection returns |
| Write fails (online) | The list does not change. "Couldn't save. Try again." (`role="alert"`, `text`, in a `surface-2` strip under the search field, a 2 px stroke info icon) and the pressed button is enabled again. The strip clears on the next attempt |
| Write pending | The pressed button shows "Saving…", keeps its size, and has `aria-disabled="true"`. It never blocks the other rows |

## Notice

- Placement: under the lead line, above the search field. It is a standing element; it does not scroll away from the top of the list.
- Pattern: `../components/neutral-notice.md` (`surface-2` fill, `line` border, `text-muted` text, 2 px stroke info icon).
- Copy, areas in the fixed order, joined with ", ":
  - Several areas: "Not suggested: {areas}. Every exercise for them is excluded."
  - One area: "Not suggested: {area}. Every exercise for it is excluded."
- It reads the stored list. Excluding the last exercise for an area is allowed, with no confirm dialog. After such a write, the status line says "Not suggested: {areas}. Every exercise for them is excluded." or the one-area form, so the change is announced.

## Accessibility (D-0199 §10)

- The status line is `role="status"` and present on mount. "Couldn't save. Try again." is `role="alert"`.
- Offline write controls use `aria-disabled`, with one `aria-describedby` target "Connect to change excluded exercises" for the whole screen.
- Labels unique: "Exclude {name}" / "Include {name} again".
- After Include again on a row in the empty-query list, the row leaves the list. Focus moves to the next row's button, or to the search field if there is none, and the status line announces it.
- Focus ring 2 px `accent`, offset 2 px. Touch targets at least 44 px (buttons, back link, clear button, search field 48 px).
- Text contrast: `text-muted` on `surface` 6.8:1 and on `surface-2` 5.8:1 (needs 4.5).
- No UF-09 control is added (principle 1).
