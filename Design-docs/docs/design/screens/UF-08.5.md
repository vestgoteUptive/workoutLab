# UF-08.5 Add exercise

- **Screen:** UF-08.5 Add exercise, a sheet over UF-08.2 Suggested workout. The UF-08.3 pattern: no URL change. Never reachable from UF-02, UF-03, UF-09 or UF-11.
- **Decisions:** D-0205 (§11), D-0203, D-0202 (Favorite tag), D-0199 (excluded list), D-0191, D-0109. Spec: `docs/specs/uf-08-add-and-reorder.md`. Modelled on `UF-08.3-UF-05.1.md` and `UF-11.6.md`; where this file is silent, those apply.
- **Foundation classes (D-0203):** `.wl-page`, `.wl-card`, `.wl-row`, `.wl-label`. Tokens: existing only (`bg`, `surface`, `surface-2`, `line`, `line-strong`, `text`, `text-muted`, `accent`). No new token, no hex. Components: Favorite tag pill (see `UF-08.2.md`), neutral notice.

## Layout (full-height sheet, 320 px and 390 px wide, top to bottom)

1. Header: title "Add exercise" (Big Shoulders Display, uppercase) and **Close** (44 px target, top right).
2. Lead line, `text-muted`: "The rest of your workout adjusts to fit {n} min."
3. Search field, visible label "Search exercises", `type="search"`, 48 px tall, `line-strong` 1 px border, `surface` fill, a 44 px clear button when it has text. **Focused on open.**
4. Status line, `role="status"`, present on mount, empty until used. It holds the Add result ("{name} added." is announced on UF-08.2) and the refusal text below.
5. The list: sections with an empty query, results with a query.

At 320 px nothing scrolls sideways; names and area lines wrap, never truncate. The sheet body scrolls; header and search stay visible.

## Empty query

1. **Favorites** (`h2`, `.wl-label`): stored favorites, by name then id, one `.wl-card`. Omitted when there are none.
2. **Today's areas**: one `.wl-card` per area of a current item in the fixed area order (chest, back, shoulders, arms, core, glutes, quads, hamstrings, calves), each with the area as an `h2` in `.wl-label`. Inside: exercises with weight 1.0 in that area, by name then id. An exercise already shown under Favorites is not repeated. Each section is a `<section aria-labelledby>`.
3. **No items (all removed):** Favorites only, then "Search to find an exercise." (`text-muted`, centred). With neither: only that line.
4. Warm-up moves never appear. Each exercise can appear under several areas; the Add button's accessible name then ends with the area: "Add {name}, {area}". Otherwise "Add {name}".

## Query

A flat list of `.wl-card` rows: case-insensitive substring of the name over every exercise, by name then id. No match: "No exercises match “{query}”." (`text-muted`, centred). No section headings.

## Result row

- Min 64 px, wraps. Line 1: name (DM Sans 700, 16 px, `text`) and, for a favorite, the "Favorite" tag after it (same pill as UF-08.2). Line 2: primary areas ("Back, Quads", `text-muted`, 13 px). Line 3 (only when disabled): the reason line (`text-muted`, 13 px).
- Actions below the text, in a wrapping group with 8 px gaps, each at least 44 px tall and 96 px wide:
  - **Add** (secondary: `line-strong` border, `text`). Accessible name "Add {name}".
  - **Start with this** (secondary), compound exercises only. Accessible name "Start with {name}". Not shown for isolation exercises.
- Add is a secondary button on purpose: the sheet has no primary action.

## Disabled rows

The first match wins; the text is the only signal (no colour, no icon). Disabled buttons keep their size, stay focusable, are dimmed (`text-muted` text), have `aria-disabled="true"` and `aria-describedby` pointing at the row's reason line.

| Order | Reason line | Add | Start with this |
|---|---|---|---|
| 1 | "In this workout" | disabled | enabled if a non-main compound; absent if the main lift or an isolation |
| 2 | "Excluded. Include it again in Plan › Excluded exercises." | disabled | disabled |
| 3 | "Not available with your equipment" | disabled | disabled |
| 4 | "Above your level" | disabled | disabled |
| 5 | "Skipping {Area} today" | disabled | disabled |
| 6 | "{Area} is recovering" | disabled | disabled |

An exercise removed on this visit is not disabled. The sheet never writes the excluded list; the row only says where to do it (plain text, not a link).

## Refusal status line

When Add or Start with this does not fit, the sheet stays open and the status line (a `surface-2` neutral notice with the 2 px info icon, directly under the search field, `role="status"`) says one of:

- "This workout has 8 exercises, the most it can hold."
- "This workout already has two {Area} exercises."
- "{name} doesn't fit in {n} min. Start with it instead, or pick more time." (compound, Add)
- "{name} doesn't fit in {n} min. Pick more time." (isolation, or Start with this)

The text clears on the next attempt or when the sheet closes. Not the attention colour. Focus stays on the button used.

## States and focus

| State | What shows |
|---|---|
| Online / offline | Identical. Search, Add and Start with this run on the device from the cached library, favorites and excluded list. No offline state, no offline line |
| Empty query, plan and favorites | Both sections |
| Empty query, no favorites | "Today's areas" only |
| Empty query, no items | Favorites only, then "Search to find an exercise." |
| Query with matches / without | Flat list / "No exercises match “{query}”." |
| Refused | Sheet open, refusal in the status line |
| Success | Sheet closes, focus on the new row on UF-08.2 |

Close, Escape and browser Back close the sheet without a change and return focus to the "Add exercise" button. The sheet traps focus while open. Focus ring 2 px `accent`, offset 2 px.

## Accessibility

- Dialog `role="dialog"`, `aria-modal`, labelled by "Add exercise". Search is labelled, not placeholder only.
- Names unique per row: "Add {name}", "Start with {name}"; the visible text starts the name (WCAG 2.5.3).
- Targets at least 44 px (WCAG 2.5.8). `text-muted` on `surface` 6.8:1, on `surface-2` 5.8:1.
- The status line is present on mount. The disabled reason is read with the button through `aria-describedby`.
- Build: web-feature:UF-08 (T-0573 to T-0577).
