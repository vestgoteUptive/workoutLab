# UF-09.3 Current set and UF-09.4 Confirm set: the weight step and the "same weight again" reason

- **Screens:** UF-09.3 Current set and UF-09.4 Confirm set. A short note only; the screens are otherwise unchanged (prototype `prototype/`).
- **Decisions:** D-0251 (own weight step), D-0252 and D-0259 §12 (`hold_effort` copy), D-0250. Spec: `docs/specs/rir-progression-and-increments.md`. The step control itself is on UF-04.2 (`UF-04.1-UF-04.2.md`).
- **Look:** Cobalt (D-0208), unchanged. No new token.
- **Principle 1:** focus mode gets two additions, both text on the same task and neither a new step or screen: the `hold_effort` line below, and the "per arm" suffix on a flagged exercise's reps line (see "One side at a time" below). There is no banner, modal or link. **Order on UF-09.3:** the hero (including the suffix), then the `hold_effort` line.

## Weight stepper

The weight stepper in UF-09.4 steps by the exercise's step: the user's own step for that exercise, or the library default. The pre-filled weight comes from the engine and already follows the same step.

## Reason line (UF-09.3 only, `hold_effort` only)

Today UF-09 has no pre-fill reason line (`reasonLine("prefill")` returns ""; only UF-02 and UF-08 show reason lines). This spec adds **one** line, for the `hold_effort` kind only.

| `PrefillKind` | Line on UF-09.3 |
|---|---|
| `hold_effort` | Same weight again. Last time was close to failure. Leave a couple of reps in reserve and it goes up. |
| `first_time` | No line |
| `carry` | No line |
| `reentry` | No line |
| `hold_after_break` | No line |
| `increase` | No line |
| `deload` | No line |
| `hold` | No line |
| `add_rep` | No line |

- Nine kinds in all; the other eight show **no line** (unchanged from today).
- **Where:** on UF-09.3 (the current-set screen), directly under the load/reps hero, in the lift state (`[data-wl-state="lift"]`). Not on UF-09.4.
- **Style:** `--wl-ink-muted`, body-small type, plain text, left-aligned like the hero's neighbours, at most 2 lines at 320 px (copy is 99 characters). It is not a live region (no `role`, no `aria-live`): it is read in order with the screen, not announced.
- **Contrast:** in the lift state `--wl-ink-muted` resolves to the lift `ink` (white, there is no lift muted key). White on `--wl-bg` is 4.8:1, which passes 4.5:1; on the deeper `bg-deep` it is 6.1:1. So `--wl-ink-muted` stays, and `--wl-ink` is not needed.
- `hold_effort` has no placeholders: the engine outputs no reps or weight with it, so the text depends on the kind alone.
- It is static text on the same task: no banner, modal or link, and no other change in focus mode.

## One side at a time: UF-09.3 hero line (D-0261, D-0263 §4)

- **Spec:** `docs/specs/unilateral-exercises.md`. Applies only to a flagged exercise (`unilateral` is `arm`, `leg` or `side`). Not flagged: the row is unchanged, exactly as today. No new token, colour or font (D-0208).
- **Principle 1:** the word sits **inside the existing reps line**. There is no new row, step or screen; nothing is added to UF-09.9.
- **Where (current-set.tsx):** the suffix is a **nested `<span>`** with the existing `.wl-uf09__unit` style (the same size as the "kg" unit), inside the reps `HeroLine`: "× 10" followed by the span " per arm". It wraps under the number at 320 px and never truncates.
- **Screen-reader text (new):** the `<p>` gets **no `aria-label`**. Instead a **visually-hidden span** holds the full reading ("12 kg, 10 reps per arm"), and the visible text is `aria-hidden` as needed so it is not read twice. This hidden span is new work.
- **Colour:** `--wl-ink-muted`. On lift and rest the state defines no muted key, so `--wl-ink-muted` resolves to the **same white as `--wl-ink`**: there is no visual distinction between the number and the suffix there. The size of the unit span, not colour, sets it apart.

| Set | Hero lines (visible) | Hidden screen-reader text |
|---|---|---|
| Weighted, flagged | "12 kg" over "× 10" + span " per arm" | "12 kg, 10 reps per arm" |
| Bodyweight or no weight, flagged | "10 reps per arm" | "10 reps per arm" |
| Timed, flagged (timed-set.tsx) | "Hold 0:40 per side" | "Hold 0:40 per side" |
| Not flagged | "12 kg" over "× 10"; "10 reps"; "Hold 0:40" (as today) | as today |

- The word follows the flag: " per arm", " per leg" or " per side" (`perSide(word)`, below). A timed row says "per side" (side-plank).
- **Timed (timed-set.tsx):** the suffix goes after the hold target text (`holdTarget` plus `perSide`): "Hold 0:40 per side". **There is no stepper for timed holds.** A timed hold is edited in UF-03 ListView, where the seconds input has the aria-label "Set 2 seconds per side" (see the UF-03 spec file).
- **Contrast** (computed from `tokens.json`): white on lift `bg` is 4.8:1 and on lift `bg-deep` 6.1:1. Both pass 4.5:1. The rest state shows no flagged label, so it has no row here.
- **320 px:** the suffix wraps and never truncates. Targets and the rest of the screen do not move.
- **States:** flagged and not flagged are both covered above. Zero history, a return after 10 days off and time running out change nothing: the label follows the flag only. **Offline:** the flag comes from the cached library (same cache as `increment_kg`), so the line reads the same. A missing or null flag (older cache) is both sides: no label.

## One side at a time: UF-09.4 stepper (D-0261, D-0263 §5)

- **Group label:** the stepper group's `aria-label` is "Reps per arm", "Reps per leg" or "Reps per side". Not flagged: "Reps", as today. **There is no stepper for timed holds**, so there is no "Seconds per side" group here (the timed seconds input is in UF-03 ListView).
- **Buttons:** the names "More reps" and "Less reps" stay unchanged.
- **Visible caption:** one line of text under the number, in the label type size and `--wl-ink-muted`: "per arm", "per leg" or "per side". The caption is part of the group, not a new step. The **number alone** stays in the target: the caption is outside the 44 px buttons and the number.
- **Targets:** every button at least 44 px, as today.
- **Contrast:** `--wl-ink-muted` resolves to white (same as `ink`) on lift: 4.8:1 on lift `bg`, 6.1:1 on lift `bg-deep`, both at least 4.5:1.
- **320 px:** the caption wraps and never truncates.
- **Pre-fill, RIR and the 5 s auto-save are unchanged.** The saved value is the per-side count (12 saves `reps: 12`); nothing is multiplied.
- Offline and not flagged: as in the hero section above.

## One side at a time: the shared `formatReps` and `perSide` strings

This is the **single source of copy** for every label in this ticket (D-0263 §8). One module at the fixed path `apps/web/src/lib/i18n/per-side.ts` (T-0974 creates it). No flow keeps its own copy of the strings.

- `perSide(word: "arm" | "leg" | "side"): string` returns " per arm", " per leg" or " per side" (with the leading space).
- `formatReps(n: number, word: Word | null, opts: { timed?: boolean; locale: string }): string`. A null word returns today's text unchanged. The number goes through `Intl` for the locale.

| Call | Result |
|---|---|
| `formatReps(10, "arm", { locale })` | "10 reps per arm" |
| `formatReps(1, "arm", { locale })` | "1 rep per arm" |
| `formatReps(10, "leg", { locale })` | "10 reps per leg" |
| `formatReps(40, "side", { timed: true, locale })` | "40 s per side" |
| `formatReps(10, null, { locale })` | "10 reps" (today) |
| `formatReps(1, null, { locale })` | "1 rep" (today) |
| `formatReps(40, null, { timed: true, locale })` | "40 s" (today) |

Called by: UF-03 (`SummaryContent` `prText` and `en.uf03.prReps`, `prWeighted`, `prTimed`, `ListView`), UF-02 (`Today.tsx`, which duplicates `prWeighted` and `prReps`), UF-09 (`current-set.tsx`, `confirm-set.tsx`, `timed-set.tsx`) and UF-06 (`stats.ts`). Where a caller needs only the suffix (the hero span, a row such as "12 × 10", a caption) it calls `perSide`. Fixed strings, no LLM text (principle 3). No new token.

Build: `web-feature:UF-09` after this spec (T-0974 creates the helper). The UF-02 `Today.tsx` change is in scope of T-0975 (the orchestrator adds the UF-02 path there).
