# UF-08.2 Suggested workout: Removed line, area notice, Favorite tag, Add and Reorder

- **Screen:** UF-08.2 Suggested workout. Only the two new elements are specified here. The time-budget bar, items, Shuffle and the rest are unchanged.
- **Decisions:** D-0202 (Favorite tag), D-0199 (§8 notice, §9 empty states, §10 design), D-0191 (Remove without refill, Skip today). Spec: `docs/specs/excluded-exercises.md`. Empty mode (the section at the end): D-0236, D-0238, D-0239 §6–§13, D-0240 §4, spec `docs/specs/empty-start-plan.md`.
- **Look:** Cobalt + state colour (D-0208); state `plan`; patterns in `components/state-patterns.md`.
- **Type:** Familjen Grotesk through `--wl-font` (the plan font, `--wl-font-plan`), in the plan roles of `design-system.md`. Sentence case; no uppercase transforms.
- **Components:** neutral notice (`../components/neutral-notice.md`). Tokens: `--wl-raise`, `--wl-line`, `--wl-ink-muted`, `--wl-ink`.

## Removed line

- **Position:** at the end of the item list, below the last item, above the Start button area.
- **Container:** `<div role="status">` that is **present on mount**, even when empty (an empty status region renders nothing visible, takes no height). Text is added into it, so a screen reader announces changes (a region inserted already full is often missed).
- **Content:** one row per item removed **on this visit**. A row is at least 48 px tall, `--wl-raise` card with a 1 px `--wl-line` border, name wraps, never truncated.
- **Two states of each row:**

| State | Row text | Control |
|---|---|---|
| After Remove | "{name} · Never suggest" | **Never suggest**, a secondary button (`--wl-ink-muted` border, `--wl-ink`), at least 44 px tall and wide |
| After the tap | "{name} won't be suggested · Undo" | **Undo**, a text button (`--wl-ink`, underline), at least 44 px tall and wide |

- Tapping Undo deletes the stored exclusion and returns the row to "{name} · Never suggest". Tapping Never suggest stores it.
- **No timeout.** The line never disappears by itself (WCAG 2.2.1). It goes when the user leaves UF-08. It is not stored and not shown on a later visit.
- Remove itself is unchanged: one tap, no confirm (D-0191). Remove does not exclude anything by itself.
- Accessible names are unique per row: "Never suggest {name}" and "Undo, {name} won't be suggested". The visible text starts the name (WCAG 2.5.3).
- **Focus:** when the user taps Never suggest or Undo, the button is replaced by the other state. **Focus stays on the Removed line**: it moves to the new button of the same row (Never suggest to Undo, Undo to Never suggest), so a keyboard user never loses their place and focus never falls to the document. The status region announces the new row text.
- **Offline:** each Never suggest / Undo button gets `aria-disabled="true"`, dimmed, and `aria-describedby` pointing at **one** line on this screen: "Connect to change excluded exercises" (`--wl-ink-muted`, 13 px, shown once under the Removed line, only when offline and the Removed line has rows). The Removed rows themselves still appear (Remove works offline). The buttons are enabled when the connection returns, without a reload.
- **Write fails online:** the row stays in its previous state, "Couldn't save. Try again." (`role="alert"`) shows under the Removed line, and the button is enabled again.

## Area notice

- **Placement:** under the "Skipping today: …" line when that line is shown, otherwise at the top of the list under the time-budget bar. One notice per screen.
- **Pattern:** neutral (`--wl-raise`, `--wl-line` border, `--wl-ink-muted`, 2 px stroke info icon). It is **not** the attention treatment (that colour is for over-time on this screen's bar).
- **Copy**, areas in the fixed order, joined with ", ":
  - Several areas: "Not suggested: {areas}. Every exercise for them is excluded."
  - One area: "Not suggested: {area}. Every exercise for it is excluded."
- **When:** the stored list leaves an area with no exercise (engine `excludedOutAreas`). It reads the stored list only: removing every exercise of an area on this visit does not show it.
- It wraps; it is never truncated.

## Empty states

**Suggested mode** (from "Suggest my workout"):

- 0 items not caused by Remove: the existing "Nothing fits in {n} min", with the area notice above it when it applies.
- Remove emptied the plan: D-0191 §5's "No exercises left. Pick a time to rebuild." stays; the Removed line still lists the removed items.

**Empty mode** (from "Start empty", D-0236 §4):

- 0 items, for any reason (at entry, or after Remove takes the last pick): "Nothing here yet. Pick from the suggestions or add an exercise." It replaces both suggested-mode lines above. The area notice sits above it when it applies, and the Removed line still lists the removed items.
- "Looks good" is `aria-disabled="true"` with "Add at least one exercise." (see Empty mode below).

## Accessibility (D-0199 §10)

- The Removed line is a persistent `role="status"` present on mount; focus stays on it after Undo.
- Offline: `aria-disabled` plus one `aria-describedby` "Connect to change excluded exercises".
- "Couldn't save. Try again." is `role="alert"`.
- Labels unique per item. Targets at least 44 px. Focus ring 2 px `--wl-focus`, offset 2 px.
- This is UF-08 (before the workout), not UF-09: no UF-09 control is added.

## Favorite tag (D-0202)

- A text tag "Favorite" on an item row whose exercise is a favorite (stored list, read from the cache, so it shows offline). Same tag as UF-04.1: the outline `.wl-chip` form used as a label (`wl-chip wl-uf08__tag`), Familjen Grotesk (`--wl-font`) 0.875 rem (14 px), weight 600, sentence case, `--wl-ink` text, a 1 px `--wl-line` outline, pill radius, 4 × 12 px padding, no pointer and no 44 px target (it is not a control); a 12 px star icon, `aria-hidden`, may precede the word.
- **Position:** on the line with the exercise name, after it, wrapping under the name when the name is long; always **above** the reason line. It never replaces or moves the reason line, the sets-and-reps line or the swap/remove actions. At 320 px the tag wraps under the name and the actions stay on screen.
- **Display only:** no control, no tap target, no focus stop. Screen readers read it as part of the item name: "{name}, favorite".
- It shows whenever the exercise is a favorite, picked as the main lift or an accessory. Nothing tells the user why a favorite is missing; the existing reasons and time bar explain it.
- Contrast: `--wl-ink` on `plan.bg` 8.6:1, on `--wl-raise` 6.2:1 (needs 4.5). Never colour alone.
- Build: web-feature:UF-08 (T-0571).

# Add and reorder (D-0205, T-0572)

- **Decisions:** D-0205 (§11), D-0203 (foundation), D-0202, D-0199, D-0191. Spec: `docs/specs/uf-08-add-and-reorder.md`. Sheet: `UF-08.5.md`.
- **Foundation classes (D-0203):** `.wl-page`, `.wl-card`, `.wl-row`, `.wl-label`. Tokens: existing only (`--wl-bg`, `--wl-raise`, `--wl-line`, `--wl-ink-muted`, `--wl-ink`, `--wl-focus`, `--wl-on-action`). No new token, no hex. Components: neutral notice, the Favorite tag above.
- **Labels (unique per row):** "Add {name}" (UF-08.5), "Start with {name}", "Move {name} up", "Move {name} down". The visible text ("Start with this", "Move up", "Move down") starts the name (WCAG 2.5.3). Every target is at least 44 px tall and 44 px wide.

## Row additions (outside Reorder mode)

- **Reason line:** an added item shows "Added by you" (`--wl-ink-muted`, 13 px) instead of the engine reason. The "Favorite" tag stays on the name line, above the reason, exactly as above. Sets × reps · weight · minutes, Swap and Remove are unchanged.
- **Start with this:** a secondary text button ("Start with this", `--wl-ink-muted` border, `--wl-ink`, at least 44 px tall, 96 px wide) in the row's action group with Swap and Remove, on a compound item that is not the main lift only. Not on isolation items, not on the main lift. At 320 px the action group wraps to a second line; nothing overlaps and nothing is clipped. Accessible name "Start with {name}".
- **Add exercise button:** a secondary full-width button (`--wl-ink-muted` border, `--wl-ink`, 48 px tall, plus icon 2 px stroke, `aria-hidden`) under the item list and the Removed line, above Shuffle, 8 px gap to each neighbour. It opens UF-08.5 and carries `aria-haspopup="dialog"`. Not the primary action: "Looks good" stays the only `--wl-focus` button. Hidden in Reorder mode. Works offline.
- **Doesn't fit line:** one neutral notice under the list (above the Add exercise button): "Doesn't fit in {n} min: {names}." Names in add order, joined with ", ". Standing text, not the attention colour. It appears and goes when the time changes, so the text is also written into the status line below. It wraps.
- **Status line:** one `role="status"` present on mount, empty until used, below the Doesn't fit line. Messages: "{name} added.", "{name} is the main lift now.", "{name} moved to {k} of {N}.". Refusals show on the sheet, not here; empty mode makes one exception (a suggestion Add and a row's "Start with this", see Empty mode › Refusals), and D-0240 §4 another in suggested mode (an over-budget row "Start with this" or Shuffle).
- **Focus after Add / Start with this:** the sheet closes and focus goes to the new row (the "Start with this" case: to the new first row). Escape or Close on the sheet returns focus to "Add exercise".

## Reorder mode

- **Entry:** a "Reorder" button (secondary, text, 44 px tall) at the right of the list header, shown when the list has 2 or more items (the warm-up row does not count). Hidden when nothing can move.
- **While on:** the header reads "Reorder" with a "Done" button in the same place (secondary, 44 px). The list is the only thing on the screen besides the time bar (which is read only, its segments follow the display order).
- **Row content:** name, sets × reps. Right side: "Move up" and "Move down" as 44 × 44 px icon-and-text buttons (chevron 2 px stroke; the text is visible at 390 px and the icon alone below 340 px with the accessible name unchanged). Stacked vertically only if the name needs the width; each button keeps 44 px and 8 px between them. Names wrap, never truncate. Row min-height 64 px.
- **First item** has no Move up; **last item** no Move down (the button is removed, not disabled). The **warm-up row** stays first, shows no controls and is not a focus stop.
- **Hidden in the mode (not in the DOM):** Swap, Remove, Start with this, Add exercise, Shuffle, the time chips and "Looks good". Standing text already shown (area notice, Removed line, Doesn't fit line) stays as plain text with no controls. The status line stays.
- **Focus:** on entry, focus goes to the first Move control of the first row. After a move, focus stays on the same button of the moved row in its new position. At the top or bottom, where the used button disappears, focus goes to the other button of that row ("Move {name} down" at the top, "Move {name} up" at the bottom). "Done" leaves the mode with focus on "Reorder". Focus never falls to the document.
- **Announcement:** the status line says "{name} moved to {k} of {N}." (k counts items, not the warm-up row). Keyboard: Tab to the button, Enter or Space moves; no drag, no shortcut needed.
- **Main lift:** keeps its main marker wherever it sits. Order is a display permutation only.
- **Motion:** the row swap is instant, or a 150 ms position transition that is off under `prefers-reduced-motion`.
- **Offline:** identical. Reorder runs on the device.

## States

| State | What shows |
|---|---|
| Plan with items | Rows, Add exercise, Shuffle, Looks good |
| Added items | "Added by you" reason on those rows |
| Added item no longer fits | The Doesn't fit notice and its status text |

| Offline | No difference |

## Accessibility (add and reorder)

- Labels unique per row and per button; visible text starts the name. Targets at least 44 px (WCAG 2.5.8), focus ring 2 px `--wl-focus`, offset 2 px. `--wl-ink-muted` on `plan.bg` 5.9:1; text on `--wl-raise` uses `--wl-ink`, 6.2:1.
- The status line is present on mount and the only live region added.
- Order, added and main status are all text; no meaning by colour alone.
- Build: web-feature:UF-08 (T-0573 to T-0577).

# Empty mode (D-0236, D-0238, D-0239, T-0939)

## Empty mode

- **What it is:** a state of UF-08.2, not a new screen (D-0236 §2). Opened by "Start empty" on UF-08.1 (`UF-08.1.md`). The plan holds only the user's picks (engine `autoMainLift: false`, `fill: false`, D-0237) and starts with 0 items. It lasts for this visit; Back to UF-08.1 drops it. "Fill the rest for me" switches the visit to suggested mode for good.
- **Decisions:** D-0236 (entry and mode), D-0238 (Suggestions), D-0239 §6–§13 (budget line, layout, live region, focus, refusals), D-0240 §4 (over-budget guard), D-0211 §5 (words, not colour). Spec: `docs/specs/empty-start-plan.md`.
- **Tokens:** existing `--wl-` variables only (`--wl-bg`, `--wl-raise`, `--wl-line`, `--wl-ink`, `--wl-ink-muted`, `--wl-action`, `--wl-on-action`, `--wl-focus`). **No new token** (D-0239 §8), no raw colour. Type: Familjen Grotesk through `--wl-font`.
- Everything this file says about suggested mode applies to the picked rows unless this section says otherwise: Swap, Remove, Start with this, Reorder, time chips, the Skip today line, the Removed line and Never suggest, the area notice, the Favorite tag and the "Added by you" reason (D-0236 §7).

### Layout (top to bottom, D-0239 §8)

1. **The time-budget bar** and its budget line (below).
2. **The why chips** from the plan's `sessionReasons` (none while the plan is empty). The "Skipping today: …" line and the area notice as in suggested mode.
3. **Your workout:** the item list under a list header. The header is a **visible `h2` "Your workout"** (section title role, plan font, the same level as the Suggestions `h2`) with the **Reorder** button at its right, exactly where suggested mode puts Reorder (the list header, shown at 2 or more items; it is not moved). At 0 items it shows "Nothing here yet. Pick from the suggestions or add an exercise." (`--wl-ink-muted`, body size, wraps). The Removed line, the Doesn't fit line and the status line follow the list as in suggested mode.
4. **Suggestions:** its rows, then "Other suggestions", then "Fill the rest for me".
5. **"Add exercise"** (opens UF-08.5, unchanged button). It sits under Suggestions, so the main path comes first.
6. **"Looks good"**, as in suggested mode, except at 0 items (below). Reorder is not here: it stays in the Your workout list header (item 3).

The time chips stay where they are in suggested mode. At 320 px nothing scrolls sideways; names, lines and copy wrap, never truncate.

### Budget line (D-0239 §6–§7)

- **Within budget:** "{used} of {n} min · {left} min left". `used` is what today's bar shows, rounded up: `totalS` when the warm-up is in the budget (it counts the warm-up), `itemsTotalS` when the warm-up is outside it. `left` is `unusedS` rounded down. Example: 30 min, warm-up on, 0 items: "3 of 30 min · 27 min left".
- **Warm-up outside the budget:** `used` = `itemsTotalS` and today's " + warm-up" suffix follows "{n} min": "{used} of {n} min + warm-up · {left} min left", and over budget "{used} of {n} min + warm-up · {over} min over".
- **Over budget** (only after a UF-08.3 swap confirmed with `fitsBudget: false`): "{used} of {n} min · {over} min over". The bar keeps its existing `data-over` treatment. **The bar does not change colour** when over: no new colour, no new token, the words carry the state (D-0211 §5). The user-flows "turns orange" does not apply here.
- **Not `aria-live` in empty mode:** the budget line carries no `aria-live` attribute in empty mode; the status line announces the change instead (one live region, below). **Suggested mode is unchanged**: there the budget line keeps its copy ("About {m} of {n} min", "{m} min, {over} over") and its `aria-live="polite"`.

### Suggestions section (D-0238, D-0239 §8)

- **Markup:** a `<section aria-labelledby>` pointing at its `h2` "Suggestions" (section title role, plan font), then the sub-line, then a `<ul>` of `<li>` rows. No `.wl-option`; each `<li>` is a `.wl-row` (12 px vertical padding, 1 px `--wl-line` hairline).
- **Sub-line** (`--wl-ink-muted`, label role, under the `h2`, shown while there are rows): "For the areas that need work most. Fits your {left} min."
- **Row** (the UF-08.5 row anatomy, at least 64 px tall, wraps):
  - Line 1: the name (row title, `--wl-ink`), then the tags: "Favorite" when the exercise is a favorite, "Main lift" when the engine marks the item main. Both are `wl-chip wl-uf08__tag` labels, exactly the Favorite tag above (not controls, no focus stop). Screen readers read "{name}, favorite, main lift".
  - Line 2: "{sets} × {reps} · {m} min" (`--wl-ink-muted`), as in the suggestions call.
  - Line 3: the engine's one-line reason (the same `rows.ts` copy as a plan row, `--wl-ink-muted`).
  - **Add:** a `.wl-button--secondary` button below the text, visible text "Add", accessible name "Add {name}" (the visible text starts the name, WCAG 2.5.3), at least 44 px tall and 96 px wide. Tapping it adds the item (a pin, or `mainPickId` for a "Main lift" row) and recomputes the list.
- **"Other suggestions":** empty mode's Shuffle, after the rows inside the section. The Shuffle button's treatment (`.wl-button--secondary`, at least 44 px), relabelled. It changes the suggestions only, never the picks. **Hidden** when the list is empty (time full, nothing to suggest, over budget).
- **"Fill the rest for me":** a `.wl-button--text` button (at least 44 × 44 px with padding), after "Other suggestions", the last thing in the section. Hidden when there is nothing to suggest; shown when the time is full or the plan is over budget (refused then, D-0242 §1). It switches the visit to suggested mode with the picks kept (D-0236 §6): the Suggestions section goes away, the budget line returns to its suggested-mode copy and `aria-live`, and Shuffle is labelled "Shuffle" again.
- **List copy** (`--wl-ink-muted`, in place of the sub-line and the `<ul>`; the `h2` stays), first match wins:
  1. Over budget (no suggestions call is made): "Your workout is {over} min over {n} min. Remove or swap an exercise."
  2. No time left for anything: "Your {n} min are full."
  3. Every area skipped, recovering or excluded-out: "No suggestions right now. Search to add an exercise." The existing notices apply as well.

### "Looks good" at 0 items (D-0239 §11)

- `aria-disabled="true"`, **still focusable**, with `aria-describedby` pointing at the reason line "Add at least one exercise." (`--wl-ink-muted`, directly under the button). A tap does nothing. The disabled look is the primary button's (`--wl-raise` fill, `--wl-ink` text 6.2:1).
- From 1 item it is enabled, whatever the unused time (D-0236 §5). The reason line goes.

### Live region (D-0239 §9)

- In empty mode the messages below go through **one** polite live region: the existing `role="status"` line (present on mount, empty until used). The budget line is not live. "One live region" means the region that carries these messages: the **Removed line keeps its own persistent `role="status"`** (D-0199 §10, `RemovedLine.tsx`), which announces only its own row changes (Never suggest, Undo), as in suggested mode.
- Its messages:
  - "{name} added. {left} min left.": every successful Add, a suggestion row (a "Main lift" suggestion included, B3) or UF-08.5.
  - "{name} is the main lift now.": only "Start with this" (a row's, or UF-08.5's "Start with {name}").
  - "{name} moved to {k} of {N}.": Reorder.
  - The refusals below, and the time-chip "Doesn't fit in {n} min: {names}." line.
  - A UF-08.3 swap (of the main lift or a pick) announces nothing here: as today (T-0303c) focus returns to the row's Swap button, whose name "Swap {name}" carries the new exercise. `mainPickId` is set silently for a main-lift swap.
- The `role="alert"` "Couldn't save. Try again." for a failed exclusion write is unchanged.

### Focus (D-0239 §10)

- **After a suggestion Add:** focus moves to the Add button of the row now in the tapped row's place. If the tapped row was last, it moves to the new last row's Add. If no rows are left, it moves to "Add exercise".
- **After "Other suggestions":** focus stays on it. If it disappears, focus moves to "Add exercise".
- **After "Fill the rest for me":** focus moves to "Add exercise".
- **After a refusal:** focus stays on the tapped button.
- **UF-08.5 Add:** keeps D-0205 §4 (focus to the new row).
- Focus never drops to `body`.

### Refusals (D-0239 §12–§13, D-0240 §4)

**Location.** A refusal shows where the tap was. A UF-08.5 Add or "Start with {name}" refuses on the sheet (`UF-08.5.md`, D-0205 §4). A suggestion Add or a row's "Start with this" refuses in this screen's status line, and focus stays on the button. This is an explicit exception to "Refusals show on the sheet, not here" in the Status line rule above (it matches what a row's "Start with this" already does). The plan stays unchanged.

**Copy.** The first match wins:

1. **The plan is already over budget** (only after a UF-08.3 swap with `fitsBudget: false`): "Your workout is {over} min over. Remove or swap an exercise first." The swap-in is the cause, so the new pick isn't blamed.
2. **The new item itself is missing** from the result: D-0205 §4's copy: "{name} doesn't fit in {n} min. Start with it instead, or pick more time." (compound, Add), "{name} doesn't fit in {n} min. Pick more time." (isolation, or Start with this), or the cap copy ("This workout has 8 exercises, the most it can hold.", "This workout already has two {Area} exercises.").
3. **The new item fits but pushes out an existing pick or the main lift:** "{name} would push out {pick}. Pick more time or remove an exercise." `{pick}` is the first pushed-out item in plan order.

The text is standing neutral text, not the attention colour, and clears on the next attempt.

### Spec defaults (D-0242, decided)

- **"Fill the rest for me" while over budget** (D-0242 §1): it stays shown and is refused in the status line with copy 1 above, like Shuffle under D-0240 §4. While the time is full it stays shown and works (it adds nothing that doesn't fit).
- **The Suggestions sub-line** (D-0242 §2) shows only while there are rows; the list copy replaces it.
- **The empty-plan line** (D-0242 §3) replaces both suggested-mode empty lines in empty mode (D-0236 §4 names only D-0191 §5's).
- **Reorder mode** (D-0242 §4) hides the Suggestions section with the other controls (D-0205 §7 lists Shuffle; the section holds it).
- **Pending ratification (T-0939, not yet in a decision):** "Start empty" on UF-08.1 follows the primary's disabled state (`UF-08.1.md`). "Fill the rest for me" is hidden when there is nothing to suggest (nothing to fill).
