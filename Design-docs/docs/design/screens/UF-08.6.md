# UF-08.6 Area detail

- **Screen:** UF-08.6 Area detail (new, D-0276 §1): the exercises of one area of today's plan, one step down from UF-08.2 Today's plan (`UF-08.2.md`). It is where Swap, Not today, Remove, Start with this and Add exercise now live. UF-08.3 Swap and UF-08.5 Add exercise open over it as sheets.
- **Route:** a step of the setup host, `/session/setup?step=area&area={area}` (`area` is one of chest, back, shoulders, arms, core, glutes, quads, hamstrings, calves). Full screen, state `plan`, no tab bar (D-0196, D-0276 §2).
- **Cold-load rule (D-0107 §1, D-0276 §2):** the host holds the plan in memory, so a cold load, a reload or a pasted link of `?step=area&area=chest` has no plan and **lands on UF-08.1** like any unknown step (the URL is replaced with `/session/setup`). The same happens when `area` is missing or is not one of the nine. If the plan exists but does not hold that area (it was removed, for example), the step is replaced by UF-08.2 with no message.
- **Decisions:** D-0274 (areas first; §5 local Add; §3 what stays), D-0275 §8 ("Not today" is `rankSwaps` for "equipment taken" then `applySwap`), D-0276 (this screen, no new token), D-0235 (swap pins), D-0191 §4 and D-0199 (Remove, Removed line, Never suggest), D-0202 (Favorite tag), D-0205 §5 (Start with this), D-0211 §5 (state in words). Spec: `docs/specs/areas-first-planning.md`.
- **Look:** Cobalt + state colour (D-0208); state `plan`; patterns in `components/state-patterns.md`.
- **Type:** Familjen Grotesk through `--wl-font` (the plan font), plan roles of `design-system.md`. Sentence case.
- **Foundation classes (D-0203):** `.wl-page`, `.wl-row`, `.wl-label`, `.wl-chip`, `.wl-button--secondary`, `.wl-button--text`. **Tokens:** existing `--wl-*` only (`--wl-bg`, `--wl-raise`, `--wl-line`, `--wl-ink`, `--wl-ink-muted`, `--wl-focus`). **No new token, no raw colour.**
- **Reused spec text:** the Removed line, the Favorite tag and the refusal copy are specified in `UF-08.2.md` (sections "Removed line", "Favorite tag" and the Add refusals) and apply here unchanged unless this file says otherwise.

## Layout (top to bottom, 320 px and 390 px wide)

The root is `.wl-page` with `data-wl-state="plan"` and `data-screen-id="UF-08.6"`, 16 px between blocks, 28 px gutters (264 px content at 320 px, 334 px at 390 px). **Nothing scrolls sideways at 320 px or at 200 % zoom (160 CSS px wide)**; names and lines wrap, never truncate; the page scrolls vertically.

1. **Back** link at the top (`.wl-button--text`, visible text "Back", at least 44 × 44 px) to UF-08.2. The offline icon sits top right. Close (×) is not on this screen: Back is the one exit, so there is no path that skips UF-08.2 (D-0276 §2).
2. **Title** (`h1`, page title role): the area, "Chest". Under it two muted lines (`--wl-ink-muted` on `--wl-bg`, 5.9:1): "{k} sets · ~{m} min" (read-only here; the stepper is on UF-08.2) and "Last 14 days: {load} of {target} sets".
3. **Exercise rows**, a `<ul>` of `.wl-row` hairline rows on `--wl-bg`, in run order (the area's own items in the plan's automatic order). Each row (min 96 px, wraps):
   1. **Name line:** the exercise name (row title role, `--wl-ink`) then the tags: **"Favorite"** when it is a favorite, **"Main lift"** when the engine marks it main. Both are `wl-chip wl-uf08__tag` labels, not controls, no focus stop (`UF-08.2.md` › Favorite tag). Screen readers read "{name}, favorite, main lift".
   2. **Detail line:** "{sets} × {reps} · {weight} · {m} min" (`--wl-ink-muted`; a timed hold shows its seconds; a bodyweight move shows no weight).
   3. **Reason line:** the engine's one-line reason (the same `rows.ts` copy as before, `--wl-ink-muted`), or **"Added by you"** for an exercise added on this visit.
   4. **How to** link: a text link "How to" (accessible name "How to do {name}"), at least 44 × 44 px, opens the exercise's how-to as the existing plan row did (UF-08.2 before this change; same target, same behaviour).
   5. **Action group** (wraps, 8 px gaps, each action at least 44 px tall and 96 px wide, `.wl-button--secondary`, `--wl-ink` outline and text):
      - **Swap**, accessible name "Swap {name}": opens UF-08.3 (unchanged). A confirmed swap-in becomes a pin and the swapped-out exercise is excluded for the visit (D-0235).
      - **Not today**, accessible name "Not today, {name}": replaces the exercise with the engine's best alternative for "equipment taken", for this visit only, and shows the Not today line (below).
      - **Remove**, accessible name "Remove {name}": drops the exercise and its sets (D-0191 §4, no refill, no confirm); the Removed line shows (below).
      - **Start with this**, accessible name "Start with {name}": only on a compound that is not the main lift. It makes it the main lift (D-0205 §5) and announces "{name} is the main lift now."
      At 320 px the group wraps to a second and third line; nothing overlaps, nothing clips.
4. **Not today line and Removed line:** see below. Both sit under the list, above Add exercise.
5. **Status line:** one `role="status"` region, polite, present on mount and empty until used. It carries "{name} is the main lift now.", "{name} added. {left} min left.", "{name} replaced by {new}." and the refusals.
6. **"Add exercise":** `.wl-button--secondary`, full width, at least 48 px tall, plus icon (2 px stroke, `aria-hidden`), `aria-haspopup="dialog"`. Opens UF-08.5. Works offline. It is not the primary action; this screen has no primary button (Start is on UF-08.2).

## "Not today" (D-0275 §8)

- **What it is:** for "machine busy, or I don't have it today". One tap, no sheet, no confirm. It calls `rankSwaps` for "equipment taken" (rule 12), applies the first candidate homed in this same area (first primary area, D-0287 §4; D-0288 §1) with `applySwap`, pins the new exercise for this visit and excludes the old one for this visit only (as D-0235). **No preference is learned from it** and nothing is stored beyond the visit (the learn-from-edits spec counts swaps, not this).
- **The line:** the row is replaced in place by the new exercise, and a **Not today line** appears under the list, one row per replaced exercise on this visit: **"{old} · Not today · Undo"**. A row of this line is at least 48 px tall, `--wl-raise` card with a 1 px `--wl-line` border, text `--wl-ink` (6.2:1 on `--wl-raise`; never `--wl-ink-muted` there, which is 4.2:1), the name wraps. **Undo** is a text button (`--wl-ink`, underline, at least 44 × 44 px), accessible name "Undo Not today, {old}". The line is the same pattern as the Removed line and shares its rules: **no timeout** (WCAG 2.2.1), it goes when the user leaves UF-08, it is not stored.
- **Undo:** restores the old exercise in the place of the new one, with the same sets, and drops the pin and the visit exclusion made by this Not today. The line row goes. Status: "{old} is back."
- **Focus:** after Not today, focus moves to the **Not today** button of the row now holding the new exercise (the same position). After Undo, focus moves to the **Not today** button of the restored row. Focus never falls to the document.
- **No alternative:** the exercise stays and the status line says **"No other exercise for {Area} today. Use Swap."** (standing neutral text, not the attention colour, clears on the next tap). Focus stays on the button. The button is **not** disabled beforehand (the engine answers on the tap), so there is no dimmed state to explain.
- Offline: identical (the engine runs on the device).

## Remove and the Removed line

- **Remove** is one tap, no confirm, and does not exclude anything (D-0191). The row goes; the area keeps its other exercises. Focus moves to the first action of the row now in that place, or to "Add exercise" when it was the last row. Status: "{name} removed."
- **The Removed line** is exactly `UF-08.2.md` › Removed line (one row per item removed on this visit, "{name} · Never suggest", then "{name} won't be suggested · Undo"; persistent `role="status"` present on mount; no timeout; offline buttons `aria-disabled` with the one line "Connect to change excluded exercises"; failed write "Couldn't save. Try again." as `role="alert"`). Only the items of **this area** are listed here.
- **Last exercise removed:** the area leaves the plan and the page returns to UF-08.2 (REPLACE of the step, so Back does not return to an empty area) with the status line **"{Area} removed. Add it back below."** The area is now in "Add an area" (it joined the visit's skipped areas, as the stepper's Remove does). Focus goes to the first stop of the row now in that place on UF-08.2, or to the "Add an area" summary when none is left. The Removed line's rows are not carried over (they were this screen's), but a "Never suggest" already tapped stays stored.

## Add exercise (UF-08.5, local)

- The button opens the sheet over this screen (`UF-08.5.md`, amended). The sheet's empty-query list shows **this area's exercises first**: Favorites, then the area's other exercises, then "Today's areas".
- **An Add is local** (D-0274 §5): it adds that exercise at 3 sets, else 2, **only if it fits the minutes left**, and changes nothing else in the plan (it never re-suggests another area). It is pinned for this visit so a time rebuild keeps it.
- An exercise whose area is not in the plan **adds that area** to the plan; the page stays on this screen, and the status line says "{name} added. {Area} is in your plan now."
- Refusals are UF-08.5's, unchanged (cap, time, over budget, push-out), shown on the sheet.
- **Focus:** after a successful Add the sheet closes and focus goes to the new row's Swap button; Close, Escape or browser Back on the sheet return focus to "Add exercise".

## Screen states

| State | What shows |
|---|---|
| Normal (online, area with exercises) | Title, the two muted lines, the rows with their actions, Add exercise |
| One exercise only | One row; Remove takes the area out and returns to UF-08.2 |
| Main lift in the area | The row shows the "Main lift" tag; no "Start with this" on it |
| Favorite or added by you | "Favorite" tag; "Added by you" in place of the engine reason |
| After Not today | The new row, the Not today line "{old} · Not today · Undo" under the list |
| No alternative for Not today | The row unchanged; "No other exercise for {Area} today. Use Swap." |
| After Remove | The row gone; the Removed line row "{name} · Never suggest" |
| Last exercise removed | Back on UF-08.2 with "{Area} removed. Add it back below." |
| Over budget (after a UF-08.3 swap that does not fit) | UF-08.2 says so in words; here Add is refused on the sheet with "Your workout is {over} min over. Remove or swap an exercise first."; Swap, Not today and Remove still work |
| Offline (sibling of online) | Identical (the engine runs on the device). Only Never suggest and its Undo are `aria-disabled` with "Connect to change excluded exercises" |
| Cold load, reload or unknown area | Lands on UF-08.1 (D-0107 §1); an area not in the plan lands on UF-08.2 |

## Focus

- Tab order follows the layout: Back, then for each row How to, Swap, Not today, Remove, Start with this (when shown), then the Not today and Removed line controls, then "Add exercise".
- **Back** (the link, the browser Back button or Escape from nothing open) returns to UF-08.2 with **focus on the open button of the row that was opened**. If that row is gone, focus goes to the first stop of the row now in that place, else the "Add an area" summary. The browser Back button and the Back link do the same thing.
- A sheet (UF-08.3, UF-08.5) traps focus while open; closing it returns focus to the button that opened it. Focus never drops to `body`. Focus ring 2 px `--wl-focus`, offset 2 px.

## Accessibility and contrast (WCAG 2.2 AA)

- **Targets** at least 44 px (WCAG 2.5.8): every action 44 px tall and 96 px wide, Back 44 × 44, How to 44 × 44, Add exercise 48 tall, Undo 44 × 44; 8 px between neighbours.
- **Accessible names are unique per row** and start with the visible text (WCAG 2.5.3): "Swap {name}", "Not today, {name}", "Remove {name}", "Start with {name}", "How to do {name}", "Undo Not today, {old}". No two rows share a name because an exercise appears once in the plan.
- **Contrast pairs** (from `tokens.json`, plan state): `--wl-ink` on `plan.bg` 8.6:1; `--wl-ink-muted` on `plan.bg` 5.9:1 (every muted line here sits on `--wl-bg`); `--wl-ink` on `--wl-raise` 6.2:1 (the Not today and Removed lines); `--wl-ink-muted` on `--wl-raise` is 4.2:1 and **is not used**; the outline of the actions `--wl-ink` 8.6:1 (needs 3:1); the "Favorite" tag text `--wl-ink` 8.6:1.
- State is in words: "Not today", "Added by you", "Main lift", "Favorite", the refusal lines; no meaning by colour alone (D-0211 §5). One status region added; the Removed line keeps its own `role="status"`.
- This is UF-08 (before the workout): no UF-09 control is added. Add during a workout (UF-09.9, UF-09.10) is untouched.
