# UF-11.6 Favorite exercises

- **Screen:** UF-11.6 Favorite exercises, route `/plan/favorites`. Reached only from the UF-11.2 row (see `UF-11.2.md`). Never reachable from UF-03, UF-08 or UF-09.
- **Decisions:** D-0202 (§10 design), D-0199 (mirror feature), D-0191 (toggle chip), D-0203 (visual foundation), D-0003. Spec: `docs/specs/favorite-exercises.md`. Modelled on `UF-11.5.md`; where this file is silent, UF-11.5 applies.
- **Look:** Cobalt + state colour (D-0208); state `plan`; patterns in `components/state-patterns.md`.
- **Foundation classes (D-0203):** `.wl-page` (gutter), `.wl-card` (one surface card), `.wl-row` (a list row inside a card), `.wl-label` (the group label style).
- **Tokens:** existing only: `--wl-bg`, `--wl-raise`, `--wl-line`, `--wl-ink-muted`, `--wl-ink`, `--wl-focus`, `--wl-on-action`. No new token, no hex.
- **Components:** neutral notice is not used here (no standing notice). C-03 is not used.

## Layout (390 px frame, `.wl-page`, top to bottom)

1. Back link to UF-11.2 Plan (44 px target), same as UF-11.5.
2. Title "Favorite exercises" (Big Shoulders Display, uppercase) and the lead line in `--wl-ink-muted`: "When a workout trains one of these areas, your favorites come first. Recovery, equipment and your time still decide."
3. The offline line, only offline: "Connect to change favorites" (`--wl-ink-muted`, 13 px). Its element id is the one `aria-describedby` target on this screen (shown once, never per row).
4. Search field, visible label "Search exercises" (not placeholder only), `type="search"`, `--wl-ink-muted` 1 px border, `--wl-raise` fill, 48 px tall, a 44 px clear button when it has text, no autofocus.
5. Status line (`role="status"`, present on mount, empty at first) for "Back squat added to favorites", "Back squat removed from favorites" and the move lines below.
6. The write-failure strip (only after a failed write, see States).
7. The list: with an empty query the grouped favorites; with a query the results.

## Empty query: favorites grouped by area

- One `.wl-card` per area that has a favorite, in the fixed area order (chest, back, shoulders, arms, core, glutes, quads, hamstrings, calves). Areas without a favorite are not rendered. 8 px gap between cards.
- Each card starts with the area name as an `h2` in `.wl-label` style ("Glutes").
- An exercise appears under each area where it has weight 1.0 (Back squat under Glutes and Quads). Inside an area: by name, then id.
- Each `.wl-row` is at least 64 px tall and wraps rather than truncates. Left: name (DM Sans 700, 16 px, `--wl-ink`, wraps) and, when the engine can't use it, one status line (`--wl-ink-muted`, 13 px):
  - "Not available with your equipment" when `isEligible(e, {...profile, level: "advanced"}, [])` is false;
  - otherwise "Above your level" when `isEligible(e, profile, [])` is false.
  The status line is text; no colour or icon carries it. Right: the **Remove** button, secondary (`--wl-ink-muted` border, `--wl-ink`), at least 44 px tall and 96 px wide.
- Accessible name of the button: "Remove {name} from favorites". The visible text "Remove" starts the name (WCAG 2.5.3). The status line is linked to the row text, so a screen reader reads "{name}, Not available with your equipment".

## Query: search results

- Case-insensitive substring of the name over every library row of kind `exercise` (any level or equipment), sorted by name, then id. Warm-up moves never appear. Results are a flat list of `.wl-card` rows, not grouped (no area headings).
- Row: name (as above), below it the primary areas ("Chest, Shoulders", `--wl-ink-muted`, 13 px). If the exercise is excluded, a text tag "Excluded" after the areas (pill: `--wl-raise` fill, 1 px `--wl-line` border, DM Sans 700, 11 px, uppercase, 0.08em tracking, `--wl-ink-muted`; same style as the UF-04.1 tag). The words are the signal, not the pill.

| Result is | Row text | Control |
|---|---|---|
| Not a favorite | name, areas | **Add**, secondary |
| Not a favorite, excluded | name, areas, "Excluded" tag | **Add**, secondary (moves it, see below) |
| A favorite | name, areas, "Favorite" tag (same pill style) | **Remove**, secondary |

- Accessible names: "Add {name} to favorites" and "Remove {name} from favorites". They are unique per screen: with a query, a name appears once. With an empty query an exercise with two weight-1.0 areas (Back squat under Glutes and Quads) has two Remove buttons; each group is a `<section aria-labelledby>` of its area `h2`, and the button's accessible name is "Remove {name} from favorites, {area}" there (the visible "Remove" still starts it). The three forms ("Favorite {name}" on UF-04.2, "Add …", "Remove …") never collide.
- Buttons are at least 44 px tall and 96 px wide.

## Move status lines (`role="status"`)

- Add on an excluded exercise: "{name} is a favorite and will be suggested again."
- A favorite that becomes excluded (from another screen) is already gone from the list when this screen renders; nothing extra shows here.
- Plain Add and Remove: "{name} added to favorites" / "{name} removed from favorites".

## States

| State | What shows |
|---|---|
| Loading | Three `--wl-raise` skeleton rows. The cache shows at once when it exists, so a skeleton appears only on first load |
| Non-empty | The grouped cards above |
| Empty, no query | "No favorites yet. Search to add one, or tap Favorite on an exercise." (`--wl-ink-muted`, centred in the list area) |
| Empty, with query | "No exercises match “{query}”." (same style) |
| Offline | The list reads from this user's cache. Search still works. Every Add / Remove button has `aria-disabled="true"` and `aria-describedby` pointing at the one offline line, is dimmed (`--wl-ink-muted` text), keeps its size and stays focusable. They are enabled again without a reload when the connection returns |
| Write fails (online) | The list does not change. "Couldn't save. Try again." (`role="alert"`, `--wl-ink`, in a `--wl-raise` strip under the search field, 2 px stroke info icon). The pressed button is enabled again. The strip clears on the next attempt |
| Write pending | The pressed button shows "Saving…", keeps its size, has `aria-disabled="true"`. It never blocks other rows |
| Time running out, 10 days away | No visual change (favorites never expire) |

## Layout at 320 px

Rows wrap: the name and status line take the full row width, and the button drops under them, left-aligned, when name and button no longer fit side by side. No horizontal scroll; the button stays at least 44 px tall and 96 px wide.

## Accessibility (D-0202 §10)

- The status line is `role="status"` and present on mount. "Couldn't save. Try again." is `role="alert"`.
- Offline write controls use `aria-disabled` plus one `aria-describedby` "Connect to change favorites" for the whole screen.
- Labels unique: "Add {name} to favorites" / "Remove {name} from favorites".
- After Remove on a row in the empty-query list the row leaves the list (a group card leaves with its last row). Focus moves to the next row's Remove button, or to the search field if there is none; the status line announces it. After Add in search results the row stays and its button swaps to Remove in the same place; focus stays on it.
- Never colour alone: "Favorite", "Excluded", the status lines and area headings are words.
- Focus ring 2 px `--wl-focus`, offset 2 px. Targets at least 44 px (buttons, back link, clear button; search field 48 px).
- Contrast: `--wl-ink-muted` on `plan.bg` 5.9:1 (needs 4.5); text on `--wl-raise` uses `--wl-ink`, 6.2:1.
- No UF-09 control is added (principle 1).
